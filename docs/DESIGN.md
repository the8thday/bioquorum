# BioQuorum 设计理念

> 2026-11-17 · 这份文档回答"我们为什么这样做"。怎么做见 [ARCHITECTURE.md](ARCHITECTURE.md)，做什么见 [PRODUCT.md](PRODUCT.md)，先后顺序见 [../ROADMAP.md](../ROADMAP.md)。
> 四份文档冲突时，本文优先：先改本文，再改其余三份。

## 一句话

**BioQuorum 交出来的不是一段回答，而是一份研究记录：每个数字连着算出它的代码，每条引用连着原文里的那句话，每个结论标着它被验证到了哪一步。**

## 1. 要解决的问题

模型已经能写出像样的分析。科研人员用不起来，原因不在生成，在核对：一份 AI 写的靶点报告有四十个数字、二十条引用，读的人要么全信，要么全部自己查一遍。全信会出事，全查就没省下时间。

所以 AI 做科研的瓶颈是**核对成本**。BioQuorum 的全部设计只为一件事：让核对一条结论的成本降到点一下鼠标。

通用功能（对话、kernel、数据库连接器、skills 数量）已经有 Claude Science 和三个开源项目在做，一个人加一个 AI 拼不过广度。我们只在这一点上做到最深。

## 2. 八条判断

每条判断后面是它在设计上的后果。

**① 证据先于措辞。**
事后审查一段写好的文字，是在猜它的数字从哪来。v0.1 的 `value_match` 就是这样：数字在证据里出现过就算通过，编造的数字碰巧出现过也通过。
→ 结论在写出来的那一刻就绑定证据。读者看到的数字是从 run 的输出里取出来填进去的，不是模型打出来的字；引用必须带原文里的一句原话，这句话能在检索到的来源里逐字找到。没绑定的内容不拦截，但明确显示为"仅为断言"。（ADR-014）

**② 信任靠机制挣得，不靠模型的口气，也不靠另一个模型的意见。**
我们自己的对照实验表明：换一家模型来审，并不比同一家多抓到错误；起作用的是可以机械核对的东西。
→ 一条结论的可信度是一级一级挣来的：断言 → 有据（绑定成立）→ 已审查 → 已复现（同一份代码重跑一致）→ 已独立重复（另一次不知道答案的独立分析得到同样的量）。最高一级是科学本来的标准，也是 Quorum 这个名字的意思。不适用的级别显示"不适用"，不假装通过。（ADR-015）

**③ 纪律放在 harness 里，不指望模型自觉。**
"任何模型 + 这套 harness 都能用"是可以测量的：同一个模型，裸跑和带 harness，在同一组题上差多少。
→ agent 层的每个机制（计划、子任务、压缩、绑定退回）都能单独开关，合入时附带没参与调参的数据上的前后对比；没有提升的机制删掉或默认关闭。（ADR-018）

**④ 研究记录是产品，对话是方向盘。**
聊天记录没人回头读。留得下来的是那份带证据的记录。
→ 界面的中心是记录（问题、计划、发现、图表、每条结论的状态），点任何一处展开证据；对话和 agent 的活动流在旁边，用来指挥。界面提前做，因为证据绑定只有看得见才有价值。（ADR-016）

**⑤ 科学家是 PI，agent 是实验室。**
问什么问题、用什么方法、结论算不算成立，是人的决定。
→ 多步分析先交计划，批准后执行；偏离计划要写明并留在记录里；任何时候可以打断、改方向、分叉会话。agent 做的分析选择（阈值、过滤、检验方法）是记录的一部分，不藏在代码里。

**⑥ 如实。**
失败的步骤、没查到的数据、没验证的结论，和成功的部分一样显示。
→ 产品里没有"看起来都对"的默认状态：未验证就是灰的。对外只说测过的话；测出来不成立的假设公开撤回（ADR-011 → ADR-013 就是先例）。

**⑦ 本地优先。**
数据在用户自己的机器上，零遥测，分级策略硬性执行。
→ 模型生成的代码在隔离的 kernel 里跑，默认不能联网；联网只能经过有权限、有审计的工具。（ADR-017）

**⑧ 少而深。**
→ 三个北极星场景做到能经得起行内人挑剔，不追 skill 和连接器的数量；生态靠兼容（MCP、Agent Skills）而不是自己堆。

## 3. 保留什么，改了什么

**保留**（v0.1 的地基是对的，一行不动）：分层与依赖方向、事件日志唯一写入路径、自有消息格式、`invoke()` 咽喉、工具返回不可信、ID 与哈希规则、`Kernel` 接口、manifest、评测纪律。ADR-001 到 010 和 013 继续有效。

安全与审计同样保留，并且加强：权限卡片、数据分级的硬性拒绝、只追加的审计日志、零遥测、密钥不进日志和模型上下文，都是 v0.1 已有的；ADR-017 补上了 v0.1 最大的缺口（kernel 里的代码能自己联网）。它们不再是主打口号，但仍是承重原则（ARCHITECTURE §1 第 10 条），也是药企能用这个产品的前提。

**改动**：

| 原来 | 现在 | 理由 |
|---|---|---|
| 写完回答再逐条审查（事后） | 写的时候绑定证据，审查只处理剩下需要判断的部分 | 判断① |
| 状态：未验证 / 已审查 / 已复现 | 加"有据"和"已独立重复"两级 | 判断② |
| 共识模式放在 v0.6 以后 | 独立重复提前，成为验证的最高一级 | 判断② |
| Web UI 推到 v0.4，三栏聊天布局 | 紧接 v0.2 开始，以记录为中心 | 判断④，取代 ADR-012 |
| kernel 隔离方案待定 | 定为 bubblewrap，网络默认关闭 | 判断⑦ |
| 首次公开发布是无界面的 CLI 预览 | 悄悄可安装在先；正式发布等到"60 秒演示"成立 | 第 4 节 |
| agent 循环 12 步上限、无计划、无压缩 | 按预算运行，机制逐个加、逐个测 | 判断③ |

## 4. 设计的验收：60 秒演示

设计对不对，用下面这段演示能不能成立来检验。做不出来的版本不正式发布。

1. 提一个问题："评估 TYK2 作为银屑病靶点。"
2. 看着记录一段一段长出来：计划、每一步的发现、图。
3. 点报告里任意一个数字，右侧展开：算出它的代码、输出、图、输入数据的 hash。
4. 点任意一条引用，展开原文，那句原话高亮。
5. 有一句话是灰的：模型凭记忆写的，没有证据。界面没有替它遮掩。
6. 点"独立重复"：另一个 agent 在不知道答案的情况下重做关键计算。数字一致，标记升级；不一致，两边的差异并排显示。
7. 导出研究包，在另一台机器上 `rerun.sh`，结果一致。

## 5. 现在还不知道的事

- **较弱的模型能不能按绑定语法写。** 不知道。v0.2 第一件事就是在三家模型上测遵从率；不够高就加一遍"补绑定"的步骤，或者对弱模型降级。
- **绑定会不会让回答变得生硬、变慢。** 要测回答质量（评测题的 rubric 得分）在开启绑定前后的变化。
- **独立重复的成本和假不一致率。** 两次独立分析因为合理的方法差异而得到不同的数，这是发现还是噪声，需要用真实任务看。
- **界面的形态。** "以记录为中心"是判断，不是结论；第一版做出来由作者按第 4 节走一遍再定。

这些问题的答案会写进 `docs/research/`，按 AGENTS.md 的评测纪律，看过的和没看过的数据分开报告。

2026-11-18 初测中，绑定提示在合成留出题上带来了更多可追溯结论，数值绑定仍取决于模型能否完成计算并在回答中引用记录。自动退回默认关闭，等用同一批有错误标记的回答测到真实修复收益后复核。 [绑定评测](research/binding-eval.md)

运行预算在调用之间决定是否继续探索，达到阈值时留一次无工具回答的机会。终端流式更新生成进度，完整正文仍在证据绑定解析后呈现。 [ADR-019](adr/019-v02-runtime-controls.md)

v0.3 的首版采用随包发布的静态前端。研究记录和审批来自事件日志，保持单人维护的
构建和依赖规模。计划要先批准，允许记录并批准偏离，开关按轮启用。分叉引用固定
历史前缀，便于并排探索同一批证据。 [ADR-021](adr/021-local-workbench.md)

v0.4 的重跑用完整的已成功内核前缀和输入快照恢复计算。只有环境及隔离匹配的结果
才可推动已审查结论升级。盲重复通过新会话和只读输入保持独立，比较规则先记录，
模型完成后才读原值。研究包保留复现所需的实际文件及绑定。 [ADR-022](adr/022-verification-and-portable-record.md)

v0.5 首批把会话上下文按用途取用。Skill 先发现再读取；项目笔记只在需要旧决定时读，
并通过版本检查保护作者保存的内容。两类材料都不能充当结论证据。
[ADR-023](adr/023-project-skills-and-notes.md)

文献子任务使用独立事件流。交办问题、只读工具白名单和已有权限构成子任务的工作范围。主会话引用逐字核对的摘录，读者可回到实际的工具结果；子任务与主回答共用预算。显式 `/literature` 让研究者决定何时使用独立检索。 [ADR-024](adr/024-literature-subtasks.md)

文献与计算共用研究包的证据和文件校验。Methods 草稿从记录生成，模型无需重述自己做了什么。检索文本进 kernel 时作为单独的输入文件留痕，图片只有在项目和接收模型均明确开启时才传输。语义审查依据实际绑定的来源，缺判定的结论停在原级别。 [ADR-025](adr/025-research-record-handoffs.md)

私有部署保留单用户 loopback 工作台。远程访问通过 SSH 转发，审计读取原事件。已配置的出站请求经专用 HTTPS 代理，离线连接器与内核由操作系统隔离。 [ADR-026](adr/026-private-runtime.md)

一次审查抽取到零条结论，或者引用缺少语义判定时，读者需要在答案和导出包中看到这项限制。复现比较要覆盖结论指向的每个运行；记录的隔离环境不可用时应在运行原代码前停止。实现约定见 [ADR-027](adr/027-review-and-replay-integrity.md)。
