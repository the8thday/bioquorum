# BioQuorum 设计理念

> 我并实质参与过抗体药物的研发。那我想试一下，只通过这套Harness加最好的模型，可不可以得到一个候选抗体序列,并把一个抗体序列推到PCC阶段

2026-11-20，作者与 AI 从 Agent first 谈到人如何与 Agent 共同做科研，并写下上面的项目初衷。[设计讨论原文](discussions/2026-11-20-agent-first.md)按北京时间记录了提问、答复和作者批注，可追溯每一轮讨论。

这句话是作者的个人目标，也是项目的宣传语和长期的试金石。它需要真实的实验，时间不由软件决定，也不限定产品范围：BioQuorum 服务于生物医药研发的各类研究工作（ADR-028）。

同日的设计复核改了四处：判断⑤重写，新增判断⑨和⑩，判断③补充推荐配置和对照（ADR-028、030、031、032）；工作台前端改用组件化工程（ADR-029）。改动理由见第 3 节末尾。

## 一句话

**BioQuorum 交出来的不是一段回答，而是一份研究记录：每个数字连着算出它的代码，每条引用连着原文里的那句话，每个结论标着它被验证到了哪一步。**

**研究者可以把一件真实而繁琐的科研工作交给 Agent；回来时既拿到它尽力做出的判断，也拿到足以质疑、修正并继续这项工作的依据。**

## 1. 要解决的问题

模型已经能写出像样的分析。科研人员用不起来，原因不在生成，在核对：一份 AI 写的靶点报告有四十个数字、二十条引用，读的人要么全信，要么全部自己查一遍。全信会出事，全查就没省下时间。

所以 AI 做科研的第一个瓶颈是**核对成本**。BioQuorum 的设计首先为这件事：让核对一条结论的成本降到点一下鼠标。

核对解决的是"写出来的话对不对"。实际用下来还有两个问题同样要紧。一是**查得够不够**：每句话都能追溯的报告，仍可能漏掉最重要的那项研究（判断⑨）。二是**工作能不能延续**：模型接触到的只是关于现实的一部分记录，材料会更正，工作会换人；这需要一个比单次对话活得更久的工作环境（判断⑩）。这也是专用 harness 相对"通用 Agent 加几个 Skill"的存在理由，成立与否用对照实验检验（ADR-032）。

通用功能（对话、kernel、数据库连接器、skills 数量）已经有 Claude Science 和三个开源项目在做，一个人加一个 AI 拼不过广度。我们只在这一点上做到最深。

## 2. 十条判断

每条判断后面是它在设计上的后果。

**① 证据先于措辞。**
事后审查一段写好的文字，是在猜它的数字从哪来。v0.1 的 `value_match` 就是这样：数字在证据里出现过就算通过，编造的数字碰巧出现过也通过。
→ 结论在写出来的那一刻就绑定证据。读者看到的数字是从 run 的输出里取出来填进去的，不是模型打出来的字；引用必须带原文里的一句原话，这句话能在检索到的来源里逐字找到。没绑定的内容不拦截，但明确显示为"仅为断言"。（ADR-014）

**② 信任靠机制挣得，不靠模型的口气，也不靠另一个模型的意见。**
我们自己的对照实验表明：换一家模型来审，并不比同一家多抓到错误；起作用的是可以机械核对的东西。
→ 一条结论的可信度是一级一级挣来的：断言 → 有据（绑定成立）→ 已审查 → 已复现（同一份代码重跑一致）→ 已独立重复（另一次不知道答案的独立分析得到同样的量）。最高一级是科学本来的标准，也是 Quorum 这个名字的意思。不适用的级别显示"不适用"，不假装通过。（ADR-015）

**③ 纪律放在 harness 里，不指望模型自觉。**
"任何模型 + 这套 harness 都能用"是可以测量的：同一个模型，裸跑和带 harness，在同一组题上差多少。
→ agent 层的每个机制（计划、子任务、压缩、绑定退回）都能单独开关，合入时附带没参与调参的数据上的前后对比；没有提升的机制删掉或默认关闭。（ADR-018）
→ 开关不能全部留给用户去试：有可测收益的机制组成一套推荐配置，新项目开箱就用它。产品值不值得专门来用，和配置良好的通用 Agent 比，不只和自己的裸跑比。（ADR-032）

**④ 研究记录是产品，对话是方向盘。**
聊天记录没人回头读。留得下来的是那份带证据的记录。
→ 界面的中心是记录（问题、计划、发现、图表、每条结论的状态），点任何一处展开证据；对话和 agent 的活动流在旁边，用来指挥。界面提前做，因为证据绑定只有看得见才有价值。（ADR-016）

工作台把项目和会话放在左侧，正文按问题和发现连续阅读。使用量、上下文和活动各有独立面板。作者的 0.7 实测中，八列用量表在侧栏把数字从中截断，因此改用上下排列的指标，并把低频会话操作收进菜单（ADR-034）。

**⑤ 交得出去，接得回来。**
研究者常常只带来一个模糊的念头，看过第一轮调查才知道自己在意什么。每一步都等人批准，浪费 Agent 的能力，也不给结论增加证据。谁掌握了能改变判断的信息，谁就在那个时刻推动研究。
→ Agent 先做能独立完成的调查，给出有依据的判断，并把最值得讨论的分歧和下一步最有价值的检索或实验留在记录里。人的决定集中在三处：这项研究服务于什么决定、会改变结论的科学分歧、资源投入和对外承诺。计划审批是可选项，不是默认流程；任何时候可以打断、改方向、分叉会话。agent 做的分析选择（阈值、过滤、检验方法）是记录的一部分，不藏在代码里。人的批准不提升结论的可信度等级。（ADR-028）

**⑥ 如实。**
失败的步骤、没查到的数据、没验证的结论，和成功的部分一样显示。
→ 产品里没有"看起来都对"的默认状态：未验证就是灰的。对外只说测过的话；测出来不成立的假设公开撤回（ADR-011 → ADR-013 就是先例）。

**⑦ 本地优先。**
数据在用户自己的机器上，零遥测，分级策略硬性执行。
→ 模型生成的代码在隔离的 kernel 里跑，默认不能联网；联网只能经过有权限、有审计的工具。（ADR-017）

**⑧ 少而深。**
→ 几个北极星场景做到能经得起行内人挑剔，不追 skill 和连接器的数量；生态靠兼容（MCP、Agent Skills）而不是自己堆。

**⑨ 覆盖先于结论。**
证据绑定保证写出来的话能回到来源，不保证没漏。我们自己的靶点评测里，强模型的逐字绑定 70/73 有效，科学覆盖只有约 3/5；弱模型把一次空查询写成了"缺少证据"。
→ 每次研究留一份覆盖台账：打算查什么、实际查了什么、空结果覆盖了多大范围、还有什么可能改变结论。查询记录从工具事件推出，不由模型自述。"没有证据"一类的话必须指得到对应的查询。覆盖和可信度是两条独立的轴，互不替代。（ADR-030）

**⑩ 记录要比对话活得久。**
真实的研发持续数月：数据陆续回来，供应商更正交付，结论被推翻，工作换人接手。检验场景是：周五收到更正表，周四的结论还成立吗？
→ 会话之上有研究线：持续的问题、当前有效的结论、登记并带版本的材料、人做的决定。材料被更正时，依赖它的图和结论标为待复核，可以用新材料重算并新旧并排。依赖关系从已有的证据记录推出，不另外手工维护。（ADR-031）

研究线和材料登记可以先于 R 接入开发：会话已经有事件记录，上传已经留下文件哈希和可取回的原件。更正表沿用这份记录即可区分同名文件的两个版本。跨语言追溯则要等 Python 写出、R 读入的中间文件也有哈希记录。（ADR-031、040，路线图 0.9.3）

一次标签更正可以直接重算已命名的测量值，含义更广的科学解释还需要复核。研究者先看影响范围，再启动隔离内核执行原代码。新值与原值并列，旧决定继续指向保存时看见的版本，由研究者决定是否修订。接手者可从摘要返回原始证据。研究线背景读取默认关闭，四道留出题观察到的收益和额外用量已分别记录。[更正与接手](adr/041-correction-and-handoff.md) · [上下文配对评测](research/v10-program-context.md)

## 3. 保留什么，改了什么

**保留**（v0.1 的地基是对的，一行不动）：分层与依赖方向、事件日志唯一写入路径、自有消息格式、`invoke()` 咽喉、工具返回不可信、ID 与哈希规则、`Kernel` 接口、manifest、评测纪律。ADR-001 到 010 和 013 继续有效。

安全与审计同样保留，并且加强：权限卡片、数据分级的硬性拒绝、只追加的审计日志、零遥测、密钥不进日志和模型上下文，都是 v0.1 已有的；ADR-017 补上了 v0.1 最大的缺口（kernel 里的代码能自己联网）。它们不再是主打口号，但仍是承重原则（ARCHITECTURE §1 第 10 条），也是药企能用这个产品的前提。

**改动**：

| 原来 | 现在 | 理由 |
|---|---|---|
| 写完回答再逐条审查（事后） | 写的时候绑定证据，审查只处理剩下需要判断的部分 | 判断① |
| 状态：未验证 / 已审查 / 已复现 | 加"有据"和"已独立重复"两级 | 判断② |
| 共识模式放在 v0.6 以后 | 独立重复提前，成为验证的最高一级 | 判断② |
| Web UI 推到 v0.4，三栏聊天布局 | 紧接 v0.2 开始，以记录为中心 | 判断④，取代 ADR-012 |
| kernel 隔离方案待定 | 定为 bubblewrap，网络默认关闭 | 判断⑦ |
| 首次公开发布是无界面的 CLI 预览 | 悄悄可安装在先；正式发布等到"60 秒演示"成立 | 第 4 节 |
| agent 循环 12 步上限、无计划、无压缩 | 按预算运行，机制逐个加、逐个测 | 判断③ |

**2026-11-20 的改动**：

| 原来 | 现在 | 理由 |
|---|---|---|
| 方法由人决定，多步分析先批准计划 | Agent 先调查并给出判断，人在分歧和投入上决定；计划审批可选 | 判断⑤，ADR-028 |
| 只管写出来的话是否有据 | 加一条独立的轴：查得够不够 | 判断⑨，ADR-030 |
| 最大的工作单位是会话 | 会话之上有研究线，材料带版本，更正可传播 | 判断⑩，ADR-031 |
| 机制逐个默认关闭 | 有收益的机制组成推荐配置；与通用 Agent 的两天对照是 v1.0 门槛 | 判断③，ADR-032 |
| 工作台是原生 JavaScript 单文件 | 组件化的 TypeScript 工程，构建产物随包发布 | ADR-029 |
| 三个北极星场景 | 加场景 D：研究线上的材料更正 | 判断⑩ |

工作台里，相同的数字可能属于不同的计算，同名文件也可能已经更新。选中的数字应指向原 run，上传的文件应指向原始字节，示例数据独立保留；这样换模型、追问或刷新后仍然能核对出处。见 [ADR-033](adr/033-workbench-files-and-example.md)。

## 4. 设计的验收：60 秒演示

设计对不对，用下面这段演示能不能成立来检验。做不出来的版本不正式发布。

1. 提一个问题："评估 TYK2 作为银屑病靶点。"
2. 看着记录一段一段长出来：计划、每一步的发现、图。
3. 点报告里任意一个数字，右侧展开：算出它的代码、输出、图、输入数据的 hash。
4. 点任意一条引用，展开原文，那句原话高亮。
5. 有一句话是灰的：模型凭记忆写的，没有证据。界面没有替它遮掩。
6. 点"独立重复"：另一个 agent 在不知道答案的情况下重做关键计算。数字一致，标记升级；不一致，两边的差异并排显示。
7. 导出研究包，在另一台机器上 `rerun.sh`，结果一致。

v1.0 另加两项验收（ADR-032 的两天对照）。第一天：同一个模型、同一批来源，对比配置良好的通用 Agent，看谁找到关键证据、给出边界清楚的判断。第二天：换一个人接手并更正一份上游材料，看他多久弄清原结论、找全受影响之处、得到修订结果。

## 5. 现在还不知道的事

- **较弱的模型能不能按绑定语法写。** 不知道。v0.2 第一件事就是在三家模型上测遵从率；不够高就加一遍"补绑定"的步骤，或者对弱模型降级。
- **绑定会不会让回答变得生硬、变慢。** 要测回答质量（评测题的 rubric 得分）在开启绑定前后的变化。
- **独立重复的成本和假不一致率。** 两次独立分析因为合理的方法差异而得到不同的数，这是发现还是噪声，需要用真实任务看。
- **界面的形态。** "以记录为中心"是判断，不是结论；v0.7 重做工作台时把连续对话和记录排在同一栏，做出来由作者按第 4 节走一遍再定。
- **覆盖台账会不会流于形式。** 模型声明的子问题可能只是套话。用留出题上对照评分标准的覆盖率判断；没有提升就默认关闭。
- **失效传播的假警报有多少。** 依赖按文件哈希算，无关的改动也会标记全部下游。先量比例。
- **专用 harness 相对通用 Agent 到底多出多少。** 不知道。两天对照会回答，结果如实公布。

这些问题的答案会写进 `docs/research/`，按 AGENTS.md 的评测纪律，看过的和没看过的数据分开报告。

2026-11-18 初测中，绑定提示在合成留出题上带来了更多可追溯结论，数值绑定仍取决于模型能否完成计算并在回答中引用记录。自动退回默认关闭，等用同一批有错误标记的回答测到真实修复收益后复核。 [绑定评测](research/binding-eval.md)

运行预算在调用之间决定是否继续探索，达到阈值时留一次无工具回答的机会。终端流式更新生成进度，完整正文仍在证据绑定解析后呈现。 [ADR-019](adr/019-v02-runtime-controls.md)

v0.3 的首版采用随包发布的静态前端。研究记录和审批来自事件日志，保持单人维护的
构建和依赖规模。计划要先批准，允许记录并批准偏离，开关按轮启用。分叉引用固定
历史前缀，便于并排探索同一批证据。 [ADR-021](adr/021-local-workbench.md)

v0.4 的重跑用完整的已成功内核前缀和输入快照恢复计算。只有环境及隔离匹配的结果
才可推动已审查结论升级。盲重复通过新会话和只读输入保持独立，比较规则先记录，
模型完成后才读原值。研究包保留复现所需的实际文件及绑定。 [ADR-022](adr/022-verification-and-portable-record.md)

v0.5 首批把会话上下文按用途取用。Skill 先发现再读取；项目笔记只在需要旧决定时读，
并通过版本检查保护作者保存的内容。两类材料都不能充当结论证据。
[ADR-023](adr/023-project-skills-and-notes.md)

文献子任务使用独立事件流。交办问题、只读工具白名单和已有权限构成子任务的工作范围。主会话引用逐字核对的摘录，读者可回到实际的工具结果；子任务与主回答共用预算。显式 `/literature` 让研究者决定何时使用独立检索。 [ADR-024](adr/024-literature-subtasks.md)

文献与计算共用研究包的证据和文件校验。Methods 草稿从记录生成，模型无需重述自己做了什么。检索文本进 kernel 时作为单独的输入文件留痕，图片只有在项目和接收模型均明确开启时才传输。语义审查依据实际绑定的来源，缺判定的结论停在原级别。 [ADR-025](adr/025-research-record-handoffs.md)

私有部署保留单用户 loopback 工作台。远程访问通过 SSH 转发，审计读取原事件。已配置的出站请求经专用 HTTPS 代理，离线连接器与内核由操作系统隔离。 [ADR-026](adr/026-private-runtime.md)

一次审查抽取到零条结论，或者引用缺少语义判定时，读者需要在答案和导出包中看到这项限制。复现比较要覆盖结论指向的每个运行；记录的隔离环境不可用时应在运行原代码前停止。实现约定见 [ADR-027](adr/027-review-and-replay-integrity.md)。

工作台顶栏管理跨项目的显示偏好，输入区提供常用研究设置，并说明它们适用于本轮还是整个项目。选区旁编写的追问和附件先进入同一份消息草稿，由研究者决定何时发送。运行提示跟随会话事件和连接状态，等待授权时显示所需操作。作用范围见 [ADR-035](adr/035-workbench-preferences.md)。

研究者从 Home 提问，在侧栏管理当前项目的 Skills 和 MCP。扩展的安装、启用与连接测试各有独立结果，实际研究与 CLI 都读取同一份配置。[ADR-036](adr/036-project-extension-library.md)

图表和报告占用的宽度随任务而变。核对结果时，研究者可以把左栏缩成图标，将更多空间给右侧结果，同时保留追问草稿；回到对话时可收起右栏。参考截图、官方资料和交互取舍见 [ADR-037](adr/037-result-reader.md)。

v0.8 的覆盖台账按研究者本轮问题重建。声明的子问题、实际发送的检索和待补的证据分别呈现；返回数量未知时保留未知，错误响应标成失败。三类证据建议随 Skill 按需读取。推荐配置需要预先冻结的同题消融和实际费用，剩余预算不足时保留未测状态。[覆盖台账](adr/030-coverage-ledger.md) · [推荐配置](adr/032-default-profile-and-comparison.md)

0.8.7 首个候选沿用证据绑定开启的 current。128 个同题消融中，证据 Skill 的净增益集中在一道题，其余改动没有显示稳定的跨场景覆盖提升。新项目默认值的发布决定等待单独六个候选会话，题目、配置及比较口径已冻结。[确认协议](research/v08-profile.md)

v0.8 的九项消融和六题确认支持保留证据绑定。其他机制的收益集中在个别题，或需付出更高费用，因此由研究者按任务启用。项目创建时记录推荐开关，保证以后切换产品版本仍可重建当时的配置。[配置决定](adr/038-v08-recommended-profile.md)

同一项组学研究可能在 Python 完成细胞质控，再用 R 做供者配对分析。保存两段代码还不足以追溯结果，读者还要知道 R 用的是哪一份计数表。两端各自记录文件内容哈希，重跑时重新产生并核对这张表。[双语言执行决定](adr/039-bilingual-kernels.md)

研究者点击结构残基或图上的样本时，所选位置必须能随问题保存并回到原文件版本。工作台使用随包发布的本地查看器，渲染库只在打开对应文件时加载。[查看器决定](adr/042-artifact-viewers.md)

长研究按原轮次恢复（ADR-043）。保存工具结果和人工决定可以保留已完成的工作。工具执行与外部系统之间没有共同事务，结果缺失时由研究者先核对。

并行读取能缩短等待，额外的模型往返也会增加耗时。通用子任务与专家角色因此分别按项目启用，父会话可逐项核对摘录和费用。此次确认集的三个短题均由直接查询最快完成，三组各命中 6/6 条档案证据。[委派决定](adr/044-scoped-subtasks.md) · [评测记录](research/v12-scale.md)
