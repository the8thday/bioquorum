## 08:47:15 · 助手 · 研究者在何时参与

我赞成把 **Agent first** 写成 BioQuorum 的科研工作理念。它给现有设计补上了一个重要问题。现在的设计很清楚地回答了“Agent 做完以后，人怎么核对”，而 Agent first 还要回答“研究开始以后，哪些工作应该默认由 Agent 主动推进”。

我会把这条理念表述为：**研究者提出值得回答的问题，并说明这个答案将用于什么决定。Agent 有责任提出自己的研究方案、执行分析、寻找反证，在证据足够时给出明确判断。研究者在科学意义、关键取舍和结果使用上保有决定权。**

这里我尤其赞同你的一个观察。有经验的研究者也会漏读论文、沿用熟悉的方法、对自己偏好的假设更宽容。一个能同时读多个来源、调用工具、复算结果、主动检查相反解释的 Agent，在具体任务上完全可能比研究者本人做得好。**设计如果预设“模型每一步都需要人批准才更可靠”，就浪费了这种优势。** 但反过来，人点了一次“批准”，也不会给一条科学结论增加证据。

### 人最值得出现在哪里？

拿你熟悉的靶点评估举例。研究者说“评估 IL23R 作为 IBD 靶点的潜力”。Agent 可以马上检索，但这句话背后可能有两个完全不同的决定：一是判断 IL-23 通路是否参与疾病，二是判断公司是否值得立项做一支**直接针对 IL23R 的抗体**。同一组遗传学、表达和临床证据，对这两个问题的回答力度可以相差很大。尤其是针对配体 p19 的药物取得临床成功，这条证据要保留，但从它走到受体抗体立项，中间还有推理和实验要补。

在这个例子里，我认为人有三个高价值角色。

1. **说明这个研究要服务什么决定。** 研究者掌握很多任务描述里没有的背景：团队已经有什么分子、内部做过什么失败实验、这次是在决定是否投入两周验证，还是是否正式立项。这些信息改变证据门槛。Agent 应该主动发现这种歧义，最好只问一句真正影响方向的话：“你这次要决定的是通路是否值得关注，还是受体抗体是否进入验证？”
2. **和 Agent 共同处理会改变结论的科学分歧。** 查哪些库、先读哪篇原文、一个检索词没命中后怎么改，这些可以交给 Agent。真正值得把人拉进来的时刻，是 Agent 发现两种合理解释会导向不同的研发决定。它应该先把自己的判断、最强反证、最能区分两种解释的下一项实验摆出来。人可以指出它忽略的生物学背景，也应当允许它用证据推翻人的直觉。
3. **决定如何行动，并为行动负责。** “现有证据支持到哪一步”完全可以由 Agent 先下判断，而且要说清楚。“在这些不确定性下，我们愿不愿意投入样本、经费和团队时间”，则包含组织目标、机会成本和责任。研究者最有价值的签字在这里。对于纯探索分析，Agent 可以一路做到交付；对于要消耗稀缺样本的实验，即使两者得出同一个科学判断，是否行动仍是一个单独的决定。

我会据此重新理解项目里已有的那句话——**“科学家是 PI，Agent 是实验室。”** 一个好的 PI 不会规定每个检索词，也不会要求组员每改一个统计参数都来请示。他希望组员能独立形成观点，知道什么时候值得回来讨论，而且有能力告诉他：“您原先的假设，很可能不成立。”这才是我理解的 Agent first。现有设计里“用什么方法，是人的决定”这一句值得将来再推敲。研究者可以规定方法，也可以把方法选择委托给 Agent；产品应当容纳这两种科研习惯。[现有设计理念](../DESIGN.md)

**对 Harness 而言，追随领先模型有一个很具体的含义：模型越强，它可以自主作出的研究判断就越多；证据绑定、权限、研究记录和复现标准仍然成立。** 今天较弱模型需要固定检索步骤，明天更强的模型也许能自己设计出更好的路线。届时应该能关掉那些步骤，在留出题上验证效果，同时继续记录它查了什么、漏了什么、凭什么下结论。否则，今天为弱模型写的补救流程，几年后就会变成强模型能力的上限。

如果以后要判断这条理念有没有真正进入产品，我会看一个很直观的体验：**研究者提出一个有实际意义的问题之后，能否放心离开一段时间；回来时，Agent 已经完成了能独立完成的调查，给出了自己的判断，并把最值得两个人一起思考的那个分歧留在桌面上。**

## 09:46:42 · 助手 · 用靶点评估和 CRO 更正检验产品价值

作为 BioQuorum 的 owner，我的判断是：**生物医药研发值得有一套专门的科研 Harness。“Agent first”可以作为设计的出发点，不必成为第九条口号。真正值得写进设计理念的，是我们希望 Agent 把科研工作做到什么程度。**

我也会修正上一轮的一句话。我说“研究者提出值得回答的问题”，把一件最有价值的工作过早地分配给了人。研究者完全可以只带来一个模糊的念头，甚至一个有问题的前提。判断问题是否成立、已有证据能回答多少、再花一天调查会有什么价值，本身就可以由 Agent 先做。人也可以在看到第一轮调查后，才形成自己的判断。好的产品要容得下这种真实的起点。

### 一、从第一性原理看，为什么需要 Harness？

把一次科研工作拆到最后，有一个很朴素的事实：**研究者想知道现实中的某件事，而模型能直接接触到的，只是关于这件事的一部分记录。** 一篇论文、一张图、一份 CRO 交付表、某次数据库查询，以及研究者记得却从未写下来的异常，各自只描述了一部分现实。即使模型的推理能力再强，它也无法从一份标错样本的表格里，凭推理还原实验当天究竟发生了什么。

模型能力提升，能够显著改善“拿到材料以后怎么理解”。科研环境还得解决另外几个问题：它拿到了哪些材料，遗漏了哪些，使用的是哪一版，哪些观察支持哪一个判断，以及材料发生变化时，原判断是否还成立。这些事情横跨模型调用、工具、文件、人员和时间。**它们需要一个比单次对话活得更久的工作环境。** 这是我能给出的、专用 Harness 值得存在的第一性理由。

但这里要区分两个判断。**科研需要这样的能力，我的回答是肯定的。BioQuorum 值得一个研究者专门来用，则要靠实际工作证明。** Claude 已经有生命科学连接器和 Skills，连“科研问题选择”都有专门的 Skill。Rosalind Workbench 也明确把科学工具、数据查看器和可定制工作流放在一起。一个人想快速了解某个靶点，直接打开自己熟悉的 Claude 或 ChatGPT，完全合理。我们应当把配置良好的这些产品当作真实对照。[Anthropic 生命科学能力说明](https://www.anthropic.com/news/healthcare-life-sciences) · [OpenAI Rosalind Workbench 说明](https://developers.openai.com/blog/rosalind-workbench)

### 二、用“帮我调研 IL-6”检验这个判断

假设这是周一上午，研究者只发来这一句话。我期待 BioQuorum 里的 Agent 有能力先向前走一段。它可以初步梳理生物学、临床探索和竞争格局，识别出哪些问题公共资料已经回答得相当充分，哪些问题必须知道适应症、干预方式或公司已有资产才能继续。**让研究者看过一轮有信息量的调查后，再问一个值得回答的问题，比在空白页上先让他填一份需求表更好。**

调研做完，研究者打开报告时，我希望他能轻松分清四件事。

| 他真正想知道的事 | 工作台应该让他看到的东西 |
|---|---|
| **你把我的问题理解成了什么？** | 这一轮调研覆盖了哪些疾病和干预方式。直接作用于 IL-6 与作用于 IL-6R 的项目分别列出。两者可以共同回答哪些通路问题，哪些资产层面的结论需要分开。 |
| **你实际做了什么？** | 计划查的来源中，哪些真正查到了、查到哪一天、哪些请求失败。某条管线有试验注册记录时，可以点开那条记录；疗效结论需要继续找到支持它的结果材料。 |
| **你为什么这样判断？** | 点开一句关键结论，可以看到原文或计算、适用人群和终点，以及 Agent 据此多走了哪一步推断。模型已有知识可以帮助它提出线索，尚待核实的线索保留相应标记。 |
| **我还有什么理由怀疑它？** | 哪类证据还可能改变判断，有没有相反结果，以及一次空查询究竟覆盖了什么范围。下一步最值钱的检索或实验是什么，也应说得具体。 |

这里有个很重要的区别：**让人理解工作过程，并不要求研究者阅读 Agent 的内心独白，甚至不要求他浏览几十条工具日志。** 研究者需要看到的是对结论有影响的动作、依据和选择。例如，“我原先把两类药物放在了一起，后来按作用对象拆开，因此收窄了这条结论”，比“我搜索了十二次”有价值得多。原始记录可以在下一层供人核对。

我们自己的评测已经说明了为什么这一步值得做。四道靶点评估题都留下了可以校验的研究记录，但 TYK2 题里，模型把一次空查询推成了缺少遗传证据。**每一句已写出来的话都可以追溯，一份报告仍然可能因为漏掉最重要的那篇研究而误导人。** 所以我认同“证据先于措辞”，也认为它自然引出了第二个问题：这次工作是否充分寻找了足以改变结论的证据？这比再给报告增加几个固定栏目更接近科研质量。[BioQuorum 靶点评测记录](../research/v05-target-expansion.md)

### 三、最能说明产品价值的，可能是 CRO 发来更正表的那一天

设想周五下午，CRO 告诉你，周三交付表中的两个样本标签互换了。此时，研究员最想知道的是：**昨天会上讨论的那条结论还成立吗？**

这个问题要求系统把一整段工作接起来。哪份原始交付被更正，用旧表生成了哪张图，哪些结论引用过它，哪份对外材料可能需要更新。Agent 可以先找出影响范围，用更正表重算，给出前后差异。留下来的记录应当让另一个同事也能理解，为什么周四的判断在当时有其依据，而周五必须修改。至于 CRO 为什么确认标签互换，Agent 可以整理往来证据，事实源头仍是掌握原始记录的人。

**这也是我对“科研很繁琐”的理解。** 难处往往集中在少数地方，繁琐散布在每一次交接里。人的时间大量消耗在确认版本、搬运上下文、重建别人做过什么、判断某项修改波及哪里。一个科研 Harness 如果能持续接住这些事，就能给科学家还回整段可用于思考的时间。这个 CRO 场景是我会用来检验产品方向的例子，现阶段不能把整条流程算作 BioQuorum 已交付的能力。

你提到的选中段落、图中元素、蛋白结构后继续讨论，我也会用这个尺度判断它的价值。比如研究者圈中一个离群点，追问“去掉这个样本，结论还成立吗？”最有价值的交互，是新讨论能带上**这个点对应的样本、图的版本、生成代码和原始分析**。Agent 随即可以解释、重算、并列展示两种结果。选中蛋白结构上的残基也是一样，带过去的是具体结构、链、残基和当前观察。这样，一个自然的阅读动作就变成了可以执行的科研问题。这是我愿意投入精力做好这种界面的原因。

### 四、人可以少做很多决定，同时更深入地参与科学

我不主张预先划定“选方法归人、做分析归 Agent”。一个熟悉领域的研究者，可能只想在看到反常结果时介入；一个刚进入陌生领域的人，也可能正是借助 Agent 的第一轮调查，才知道自己在意什么。对两者都合适的产品，应允许 **Agent 先形成有依据的判断，人随时带着新事实、新疑问或不同解释加入。**

人在这里有几种很具体的贡献。他知道有些实验昨天刚失败，知道公司手里的抗体和公开竞品有何不同，也知道团队究竟有资源验证哪个假设。这些是 Agent 尚未获得的现实信息。与此同时，Agent 可能比任何单个人读过更多来源，可能发现整个团队默认接受的前提站不住脚。**谁掌握了能改变判断的信息，谁就应该在那个时刻推动研究。** 需要人承担的资源投入、对外承诺和科学责任可以很明确，其余地方不必靠“请批准下一步”来体现人的存在。

最后，作为 owner，我会用一个具体实验来判断我们为什么要继续开发 BioQuorum：给配置良好的通用 Agent 和 BioQuorum **同一个模型、同一批可用来源、同一项研究任务**。第一天看谁能找到关键证据、给出边界清楚的判断。第二天换一位研究者接手，再更正一份上游材料，看他要多久才能弄清原结论、找全受影响的地方、得到修订结果。两天的表现都值得测。前者检验 Agent 做科学工作的能力，后者检验这套 Harness 究竟替研究者承担了多少工作。

所以，如果让我用一句话回答“为什么开发它”，我的答案是：**让研究者可以把一件真实而繁琐的科研工作交给 Agent，回来时既拿到它尽力做出的判断，也拿到足以质疑、修正并继续这项工作的依据。** “Agent first”可以是内在本质。研究者能放心把工作交出去，又始终有能力接得回来，才是他选择 BioQuorum 的理由。
