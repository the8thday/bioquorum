# ADR-014 结论在写出时绑定证据

状态：已接受（2026-11-17）。已实现（2026-11-18，`runtime/values.py`、`review/binding.py`）。遵从率初测见 [绑定评测](../research/binding-eval.md)。

## 背景
v0.1 的审查是事后的：模型写完一段文字，再用规则去猜每个数字、每条引用从哪来。实测的两个缺口都出在这里：`value_match` 是"出现即通过"，编造的 "48 trials"、"62%" 没被标出；worker 在 kernel 里自己下载的全文，审查看不到，结论被误判为 disputed（NEXT.md，docs/research/review-checks.md）。再加规则只会让猜测更复杂。

## 决定
【承重】**读者看到的数字来自证据库，不来自模型输出的字符；读者看到的引用附带一句能在来源里逐字找到的原话。**

- 回答和报告用"记录标记"书写：Markdown 加两种绑定。
  - **计算值**：kernel 代码用 `bq.value(name, value, unit=None)` 声明，作为结构化输出记入该 Run；正文里写 `{{name}}`，渲染时填入数值。
  - **原话**：`[@PMID:123 "原话"]` 或 `[@<工具调用别名> "原话"]`。原话必须是本会话里某次工具返回文本的逐字子串（只归一化空白）。数据库工具返回的数值也用这种方式引用，或读入 kernel 后经 `bq.value` 声明。
  - 图和表按产物名引用。
- 绑定的解析是确定性的，不调用模型。全部绑定成立的结论进入 `grounded` 状态（ADR-015）。
- 没绑定的数字和引用**不是错误**：显示为"仅为断言"，v0.1 的四个确定性检查继续作用于它们，也继续用于审查外部回答（`bq review --answer-file`）。
- 绑定解析失败（名字不存在、原话找不到）时，harness 把失败项退回给模型，往返上限沿用 §6.5 的 2 次；仍失败则原样显示为失败。
- kernel 里自己读到的文献不算证据；全文必须经工具获取（与 ADR-017 的网络隔离配套）。
- 【可调】具体语法、别名规则、数值格式化方式。v0.2 的取值见下面的设计笔记。

## 设计笔记（v0.2，可调）

**命名值。** kernel 启动和重启时注入 `bq` 对象（一段代码，不依赖 kernel 里装了 bioquorum）。`bq.value(name, value, unit=None, desc=None)`：
- `name` 匹配 `[A-Za-z][A-Za-z0-9_]{0,63}`；`value` 只收标量：int、有限的 float、不超过 200 字符的 str，numpy 标量经 `.item()` 转换，bool 和其他类型报错（表格和图按产物引用）。`desc` 是这个量的定义，留给 v0.4 的独立重复。
- 它发出一条 `display_data`，MIME 为 `application/vnd.bioquorum.value+json`，同时带 `text/plain`（`bq.value n_de = 412 genes`），所以模型在 run 的输出里看得到自己声明了什么。
- `tools/runs.py` 收集这些输出，写进 `run_finished` 的新字段 `values`（`NamedValue` 列表）。**失败、超时、打断的 run 不记录命名值**，返回给模型的摘要里会说明。同一个 run 里同名取最后一次。
- 会话里同名的量取回答之前最后一次成功声明的那个。

**记录标记。**
- 计算值：`{{name}}`，或带 Python 格式说明 `{{name:.2e}}`（只允许 `[0-9.,+\- eEfFgG%]`）。缺省格式：int 原样，float 取 4 位有效数字（`.4g`；绝对值在 1e4 到 1e15 之间的取整数，避免科学计数法），str 原样。单位不自动追加，正文自己写；单位记在证据里。
- 原话：`[@来源 "原话"]`，引号也接受 `“ ”`。来源有两种：
  - 来源别名 `s1`、`s2`……：会话里每次成功的非 kernel 工具结果按事件顺序编号。模型看到的工具结果开头有一行 `[source s3]`（`agent/context.py` 按同一规则生成）。
  - 文献 ID，如 `PMID:123`、`DOI:10.x/y`：原话所在的工具结果里必须出现这个 ID。
- 原话里可以有直引号（数据库工具返回的 JSON）：原话到第一个后面紧跟 `]` 的引号为止。以 `[@` 开头但解析不了的标记算绑定失败（退回给模型），不当普通文字放过。
- 原话匹配：两边都把连续空白压成一个空格后做大小写敏感的子串比较。工具结果是 JSON 时，也和 JSON 里字符串值解码后的文本比较（同一段文字的另一种写法，不算放宽）。原话至少 8 个字符。
- `python_execute` 的输出不能当原话的来源：kernel 自己打印的文字不是证据。run 里的数字只能经 `bq.value` 绑定。

**结论的状态。** 抽取结论时原样保留标记。一条结论满足以下全部条件才是 `grounded`：至少有一个绑定；全部绑定成立；去掉标记后不再有裸露的数字和裸露的文献 ID。不算裸露数字的：行首编号；run ID；连字符接在字母后面的（`IL-23`、`COVID-19`）；紧跟在 type、phase、stage、grade、class、group、outcome、cohort、arm、cluster、chromosome、figure、table、step、tier、level、batch、sample、replicate、run 之后、不大于 10、不带单位的整数（`type 2`、`phase 3`、`outcome 0`），它们是名字，不是报告的量。绑定失败（名字不存在、原话找不到）记为 error 级 finding（检查名 `binding`），结论进入 `disputed`。没有绑定的结论通过审查后仍是 `unverified`（ADR-015：级别不能跳），界面显示为"仅为断言"。确定性检查看的是渲染后的文本：数值按**完整精度**填入（显示格式会四舍五入，`value_match` 对不上），原话写成 `"原话" [来源]`，绑定值所在的 run 算作结论引用的 run。所以 v0.1 的检查照常工作。

**退回。** 回答写完后，harness 在本地解析绑定；有失败项就以系统身份发一条消息列出失败项，让模型修正，最多 2 轮，之后原样接受。开关 `[agent] binding_retries`（0 到 2，ADR-018）。提示词里的绑定说明和来源别名行由 `[agent] binding` 控制，关掉即 v0.1 的行为，用于提升评测的对照组。

## 后果
- 需要新的事件载荷（Run 的命名值、绑定解析结果）；落地时同步更新 ARCHITECTURE §5.3 和 `bundle-spec/`。
- `citation_supports` 的任务缩小为"这句原话是否支持这条结论"，输入更短，判断更容易。
- 必须先测再信：在没参与调参的答案上报告各模型的绑定遵从率、编造数字的检出率（对比 v0.1 `value_match`）、开启绑定前后的 rubric 得分。遵从率不够的模型加"补绑定"步骤或降级，结果写进 `docs/research/`。
- 研究包导出时带上绑定关系，读者不装 BioQuorum 也能从数字追到 run。

v0.5 场景 A。语义审查读取解析后的引用和相应来源。审查未返回结论级判定时，记录缺失并保留该结论的当前等级。 [ADR-025](025-research-record-handoffs.md)
