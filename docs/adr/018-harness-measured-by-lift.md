# ADR-018 harness 的每个机制可单独开关，并用评测上的提升说话

状态：已接受（2026-11-17）。

## 背景
产品承诺是"任何模型加上这套 harness 都能做科研"。agent 层接下来要加不少机制：计划、预算、压缩、子任务、skills、项目笔记、绑定退回。这类机制很容易凭感觉堆上去，每个都增加提示词长度、费用和出错面，而对结果有没有帮助没人知道。v0.1 的 agent 循环很小（约 120 行），这是优点。

## 决定
- 【承重】agent 层的每个机制都有独立开关（配置项），关掉后循环仍然能跑。主循环保持小：机制以可插拔的步骤接入，不把循环写成分支树。
- 维护一个 harness 提升评测：同一个模型 ×（裸跑：只有 kernel 工具和最短提示词 / 带 harness）在同一组题上的 rubric 得分、绑定遵从率、费用和耗时。
- 新机制合入时附带开关前后的对比，数据必须包含没参与调参的题目，看过的和没看过的分开写（AGENTS.md 评测纪律）。
- 没有可测提升、也不降低费用的机制：删掉，或默认关闭并在文档里写明"未证实"。
- 对外说"harness 让模型 X 提升了多少"时，只引用这个评测的数字。

2026-11-18 实施记录。首轮绑定消融在合成留出题上测到了绑定提示带来的有据结论增量。自动退回在这轮的收益仍未证实，按本 ADR 默认设为 0，保留显式开启和两轮上限。复核默认值前，单独给模型同一份有错误标记的回答，对比是否成功修复和新增成本。 [评测记录](../research/binding-eval.md)

2026-11-19 复核。合成留出题里，一轮反馈能修复两套模型的大部分错误绑定。观察到正确的相邻结论被撤回，第二轮没有触发。继续默认设为 0，在真实科研场景中测触发率、修复率和额外调用。 [修复对照](../research/binding-repair-eval.md)

2026-11-19 真实数据对照。完整工作流提供了可追溯结论。在 10 个允许退回的组合中，开发题触发一次，新增 4 次 worker 调用，留出题无触发。继续默认关闭退回。 [真实研究数据对照](../research/harness-research-eval.md)

2026-11-19 运行控制对照。预算按阈值停住工具，流式在回答落盘前报告生成进度，压缩会追加摘要调用。本地小模型三题的配对结果支持将这些机制保留为独立可选项。 [运行控制对照](../research/v02-runtime-controls.md)

## 后果
- 评测题要扩充并留出一部分永不用于调参；公开基准（BixBench、LAB-Bench 子集）在 v0.4 发布前接入。
- 每个机制多一点接线成本，换来可以做消融。
- 评测要调真实模型、要花钱：手动或定期触发，不进默认 CI（§6.8 不变）。
