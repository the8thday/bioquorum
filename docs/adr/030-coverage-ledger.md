# ADR-030 覆盖台账：记录查了什么、没查到什么、还缺什么

状态：已接受（2026-11-20）。补充 ADR-014、015、018。

## 背景
证据绑定保证写出来的话能回到来源，不保证没漏掉会改变结论的证据。v0.5 的四道靶点题用强模型复测：逐字绑定 70/73 有效，对照评分标准的科学覆盖各约 3/5。本地小模型还把一次空查询写成了"缺少遗传证据"。

## 决定
- 每次研究维护一份**覆盖台账**，是研究记录的一部分：
  - 打算回答的子问题和证据类别（由 Agent 在开始时提出，可以中途增删，增删留痕）；
  - 每一类实际发出的查询：工具、查询词、时间、返回条数、失败原因；
  - 空结果只能写成"在这个来源、这个查询范围内没有找到"；
  - 收尾时列出仍未覆盖的类别，以及哪类证据最可能改变结论。
- 台账里的查询记录从工具事件推出，不由模型自述。模型只负责声明子问题、把查询归到子问题、写缺口说明。
- 【承重】覆盖是独立于可信度阶梯的另一条轴。台账不提升也不降低任何结论的等级；不为了让台账"看起来完整"放宽"已覆盖"的含义。
- 结论里出现"没有证据""未见报道"一类的否定性陈述时，必须指向台账里对应的查询；指不到的显示为"仅为断言"。
- 不按疾病或靶点写死检查清单。各类研究的证据类别建议放在 Skill 里，可以替换（AGENTS.md 评测纪律：不为单题写规则）。
- 按 ADR-018 带开关合入。评测指标是对照评分标准的覆盖率，留出题单独报告。

## 后果
- 新增事件类型（实现时定名，加入 ARCHITECTURE §5.3）和对应投影。
- 界面在记录里显示台账；研究包带上台账。
- 评测题需要给每题补"应覆盖的证据类别"，由作者确认科学内容。
