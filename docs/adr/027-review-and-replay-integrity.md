# ADR-027 审查、重放与研究包的一致性

状态：已接受。补充 ADR-014、016、017、020、022 和 026。

## 背景

CLI 和工作台可以打开同一事件库。一次审查可能抽取不到结论，一条结论也可能引用多个计算。研究包接收人需要知道哪些检查完成、哪些材料缺失。

## 决定

- 写研究记录的 CLI 命令和工作台生命周期共用项目进程锁。工作台先取得锁再恢复中断操作。重放和独立重复的结束事件与相应等级变更在同一事务提交。投影重建在同一 SQLite 写事务里按插入顺序读事件、替换投影。
- 逐答案采用最近一次结束的审查。状态变更先写，结束事件记录结论数和检查限制。旧结束事件缺少这些字段时，可从同一审查的抽取事件识别零结论。历史评级仍保存在事件日志中。
- 引用标识和原文必须来自同一可识别记录。未执行语义判定的引文最多为 grounded。重放覆盖每个绑定运行及其前置单元，在运行原代码前检查内核环境和隔离。独立重复要求每个绑定运行都有可比较的命名目标。
- 重放沿用项目隔离要求，使用临时工作目录及已验证输入。离线 MCP 仅自动获得所选命令文件，使用 BioQuorum 自身 Python 时另含该解释器环境。其它命令所需的私有运行时资料通过 read_paths 显式授予。代理下载的 DNS 解析和公网地址检查由 CONNECT 代理执行。
- 便携记录保留本次审查、调用失败与材料缺失信息。文件工具记录项目相对路径或外部文件名；下载记录保留协议、主机、路径和内容哈希。分发包限制源码文件范围，发布前检查实际归档。

## 后果

工作台打开期间，同项目的 CLI 写操作会提示项目占用。下载查询参数由请求处理器临时使用，重放使用已记录的数据对象。无法从历史记录推断的检查和缺少环境锁的本机重跑保留原有证据等级。
