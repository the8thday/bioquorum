# ADR-051 · 输入区的模型、推理强度与权限控制

接受。作者希望工作台的输入区像主流桌面 Agent 一样，在提问处直接选择模型、推理强度和权限，其他页面同步整理。

## 决定

**输入区。** 问题框下方一行工具：`+` 菜单（附加文件、研究方式、项目研究设置）、模型与推理强度选择、权限状态、发送或停止按钮。Enter 发送，Shift+Enter 换行。研究方式三选一：直接研究（默认）、先审计划、独立文献检索，取代原来两个复选框。选择只作用于本轮，随 `turn_requested` 记录；新一轮默认沿用本会话上一轮的记录值，因此界面不持有不能从事件推出的选择（ADR-016）。

**推理强度。** `turn_requested` v5 增加可选的 `reasoning_effort`（`low` / `medium` / `high`），空值表示服务商默认，v4 记录升级为空值。只作用于研究模型角色；计划、审查、压缩沿用默认。通过 Pydantic AI 统一的 `thinking` 设置传给服务商。OpenAI 与 ChatGPT 套餐默认可调；其他服务商需在 `[models."provider:model"]` 写 `reasoning = true` 才显示可调，也可写 `false` 关闭。提交时选中的模型不支持则拒绝；回退链上的模型不支持时不发送。`model_call_started` v2 记录实际发送的强度，回答旁显示的强度来自这条事件而不是请求。录制 cassette 只在设置了强度时把它并入请求键，已有录制保持有效。

**权限。** 权限请求卡片提供 Allow once、Allow for this session、Deny 三项，对应已有的 `once` 与 `session` 范围。会话授权从本会话 `permission_decided`（`scope = session`）推出，下一轮研究开始时重建，只覆盖同一权限类别和同一记录目标；记录目标经过显示路径转换或脱敏而与原目标不一致时再次询问，不会扩大授权。新增事件 `session_permissions_reset` 清除本会话此前的会话授权。输入区的权限按钮列出项目默认授权、本会话授权和需要询问的类别，并可重置会话授权。

不提供"全部自动允许"模式。数据分级拒绝、kernel 隔离和项目撤销照常生效；会话授权只是少问同一目标。

**其余页面。** 首页以问题框为中心，给出四类科研任务起点，下方列出最近会话。侧栏顶部是新建会话，导航与会话列表分开，项目工具（Skills、MCP、模型、研究工具、项目设置）收在底部。回答的可信度标记按信任阶梯分色。

## 理由

模型和推理强度会改变一轮研究的费用、耗时和结论质量，属于研究记录的一部分，所以和 `worker_model` 一样写进请求事件，并由实际调用事件确认。

推理强度是服务商参数，不是 agent 层机制；默认空值时请求与之前完全相同，因此不需要 ADR-018 的提升评测。是否值得调高由研究者按任务判断，界面不宣称某一档更准确。

权限按会话记住同一目标，是桌面 Agent 普遍提供、研究者反复确认同一数据库时最需要的一步；授权从事件重建，审计日志里能看到是谁、在哪一轮、按什么范围允许的。
