# ADR-044 · 有权限上限的并行子任务

## 背景

文献助手已有独立上下文、父会话授权和原文摘录。两个问题读取不同材料时可以同时进行，模型给出的总结仍须与可核对的原文区别对待。

## 决定

- 通用委派与专家角色分别由 `subtasks` 和 `specialists` 控制。两项默认关闭。一次委派接收 1–8 个独立问题，项目另选同时运行的上限。
- 每个问题使用独立事件流，父会话记录子任务的开始、结束、摘录、用量与费用覆盖。来源别名指向实际工具返回的原文。子任务的总结仅供调查参考。
- 子任务可用工具取父会话已登记的工具和项目白名单的交集；专家文件再限制工具名与权限类。每次调用仍须通过父会话已有授权及数据分级。专家指定的模型同样必须由项目配置并允许处理当前分级。
- 本地读取和已声明只读的内置公共查询可以并行。其他连接器和外部 MCP 调用在同批任务中串行。父子共用探索预算；有 token 或金额预算时，在启动下一次模型请求前结算前一次。单次请求可能越过探索阈值，另有硬支出上限的评测使用请求前预留。
- 文献子任务继续使用原事件格式与原入口。通用子任务使用新的开始与结束事件，重用引用、恢复和费用归集规则。

## 后果

研究者可选择并行度，核对每个问题的耗时和证据。真实短题对照中，额外的模型请求增加开销，三组证据命中相同，维持按需开启。[开关评测](../research/v12-scale.md)
