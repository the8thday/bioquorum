# ADR-016 以研究记录为中心的 Web 工作台，提前到 v0.3（取代 ADR-012）

状态：已接受（2026-11-17）。取代 [ADR-012](012-web-ui-deferred.md)。

## 背景
ADR-012 把 Web UI 推到审查层和研究包稳定之后，理由是前端耗时且不差异化。两件事变了：作者明确把"方便、好看、可交互的界面"列为产品目标；ADR-014 的证据绑定只有在界面上点得开才有价值，这时界面就是差异化本身。终端里没法"点一个数字看它的代码"。

## 决定
- v0.2（证据绑定在 CLI 里跑通）之后立即做 `server/` 和 `web/`，即 v0.3。
- 【承重】**界面不持有任何不能从事件推出的状态。** `server/` 只做两件事：把事件和投影读出来（HTTP + SSE），把用户操作转成与 CLI 相同的调用。界面不写投影表，不绕过 `invoke()`。流式 token 仍是瞬时帧，不是事件（§5.2）。
- 【承重】用户不需要 Node：前端构建产物作为静态文件随 Python 包发布。Node 只出现在开发和 CI 里。这是 ADR-001 允许的唯一例外，范围不扩大。
- 布局以**记录**为中心，不照搬"聊天 + 产物面板"：
  - 记录：问题、计划、发现、图表，每条结论带状态标记；
  - 证据抽屉：点数字看代码、输出、输入 hash；点引用看原文和高亮的原话；
  - 活动流与输入框：agent 正在做什么，随时打断和改方向；
  - 卡片：计划批准、权限、审查发现。
- 【可调】技术栈（React + Vite + TypeScript + shadcn/ui）和具体布局。第一版做完由作者按 DESIGN.md 第 4 节走一遍再定。
- CLI 和 MCP Server 仍是一等入口，三者功能来自同一套调用。
- 专业查看器（Mol*、igv.js、RDKit.js）仍然推后。

## 后果
- import-linter 增加 `server` 的契约（只有它 import FastAPI；它不被下层 import）。
- 前端测试遵守 §6.8：组件测试不联网；端到端测试对着 cassette 模型和 `FakeKernel` 的服务端跑。
- 作者不熟前端，这部分完全由 AI 维护：组件数量要克制，依赖要少。
- 发布节奏相应调整，见 ROADMAP。
