# 确定性审查检查：规则与实测（v0.1）

> 2026-11-17 · `src/bioquorum/review/checks/` · 评测脚本 `evals/review_eval.py`（不联网、不调模型）
> 复现：`uv run python evals/review_eval.py`；留出集：`uv run python evals/review_eval.py --heldout <worker...>`（需要本机的实验缓存 `evals/results/cache`）

## 四个检查（全部不调用模型）

| 检查 | 规则 |
|---|---|
| `execution_evidence` | 显式引用的 run 必须存在且成功（如实报告失败、假设语气除外）；第一人称计算（"I queried / ran / pooled…"）或报告了结果的执行类结论，必须能匹配到一个成功的 run，并且报告的数值出现在该 run 的输出里。run 的匹配用词干和数值，不用问题里的主题词。 |
| `value_match` | 结论里每个独立数字都要出现在证据里（成功 run 的代码与输出、引用的标题与摘要），允许按结论的精度四舍五入，也允许同一 run 输出里两数的和或差；单位要一致（38.5% ≠ 38.5 mg/dL，列名里的单位也算）；表格行把数值和标签绑定，标签被对调的报错（只在结论逐行读同一张表时才判断，阈值除外）。 |
| `citation_resolves` | 结论引用的每个编号 / PMID / DOI 都必须出现在本会话检索到的来源里。 |
| `plan_complete` | 已批准计划里的每一步都要完成（事件标记，或者：点名的工具/数据库要在成功 run 或回答里出现；没点名的看词覆盖率）。只对"声称完成"或"声称做了缺失步骤"的计划类结论报错，如实承认缺口的不报。 |

¹ 两条都是 DeepSeek 在没有任何 run 的情况下自己"合并"出 HR 0.72，属于真问题，只是语料没标。

## 确定性检查抓不到的（交给模型检查）

- 数值在证据里，但属于另一组 / 另一终点：ie-004（"CD" 即 Crohn's，需要领域知识）、ie-018（复合终点的 HR 被安到单一终点上）。
- 引用编号存在但内容对不上：ie-005、ie-017。
- 判断类错误：`citation_unsupported`、`stat_method`、`overclaim_causal`。

这些由 `citation_supports`（v0.1，已实现）和 `method_sanity`（后续）负责；按 ARCHITECTURE §6.5，两组的召回率和误报率分开报告。
