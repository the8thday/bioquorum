# v0.5 项目上下文消融

用同一个本地 Qwen3 4B Instruct、固定项目、同一题比较关和开。Skills 条件下文档
都在项目中，开关只改变发现和加载。笔记条件下先在另一个会话由作者保存项目规则，
再在新会话提问。题目测试能否找回合成的项目内约定，不测科学判断或通用答题质量。
没调用付费模型。

| 机制与数据 | 关闭 | 开启 |
| --- | ---: | ---: |
| Skills 初版 · 开发题 | 0/1 | 1/1 |
| Skills 初版 · 留出题 | 0/3 | 0/3 |
| 项目笔记 · 开发题 | 0/1 | 1/1 |
| 项目笔记 · 首批留出题 | 0/3 | 3/3 |
| Skills 增加结构化名称候选后 · 新留出题 | 0/3 | 3/3 |
| 项目笔记 · 新留出题 | 0/3 | 3/3 |

初版 Skills 的三次失败都没有成功打开正文。模型把描述或题目的短语当成了目录名。
据此将可用名称写进工具参数候选，保持按需读正文的同一流程，再用未见过的新题对照。
复测的两组开启分支分别消耗 9,016 和 9,072 token，关闭分支为 3,775 和 3,808。
记录的执行时间分别为 8.35 和 5.10 秒，关闭分支为 7.52 和 4.10 秒。
耗时样本很小，含本地模型冷启动和缓存影响。保持两项默认关闭，给需要项目背景的工作流
显式打开。未验证多项目、大 Skill 目录或真实研究答题质量的收益。

浏览器回归覆盖两窗口并发编辑、版本冲突后刷新、另一会话看见已保存笔记。离线自动
测试覆盖目录和符号链接边界、未激活时拒绝资源、草稿隔离、凭据拦截以及工具输出不能
成为科学引用。评测脚本为 `evals/v05_project_context_eval.py`，原始结果在本地
`evals/results/v05/project-context.json` 和 `project-context-new.json`。
