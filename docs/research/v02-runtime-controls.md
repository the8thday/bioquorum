# v0.2 运行控制对照

2026-11-19。使用本地 Ollama 的 Qwen3 4B Instruct，以相同的绑定提示、数据、工具与预置早期对话，对比基线、预算、压缩和流式四组。每组单次采样。数值答案与独立 R 输出比对。有据项要求答案正确且绑定实际运行或来源。评测不使用付费 API。

## 设置

- 开发题是 PlantGrowth，留出题是 ToothGrowth 和 sleep。题目与评分沿用冻结的 [真实研究数据对照](harness-research-eval.md)。
- 基线探索最多四步。预算组设 4,500 token 和 120 秒，再保留一次无工具回答。压缩组的上下文阈值为 3,000 字节。流式组只改变响应读取方式。
- 两次试运行发现项目内 CSV 的读取授权没有传给评测，以及输入声明错误限制到固定目录。保留这些试运行作为故障记录。正式对照给各组相同的数据读权限，使用修正后接受普通项目文件的实现。

## 结果

| 配置 | 开发题答对 | 留出题答对 | 答对且有据 | Worker 总 token | Summarizer 总 token | 平均耗时（秒） |
|---|---:|---:|---:|---:|---:|---:|
| 基线 | 1/3 | 1/8 | 0/11 | 22,930 | 0 | 13.20 |
| 预算 | 1/3 | 1/8 | 0/11 | 23,781 | 0 | 17.93 |
| 压缩 | 1/3 | 0/8 | 0/11 | 25,584 | 14,076 | 54.45 |
| 流式 | 0/3 | 0/8 | 0/11 | 41,271 | 0 | 42.59 |

十二个组合均返回回答。其中四次 kernel 执行成功，常见失败是模型猜错了列名，或生成的 Python 有语法错误。预算在三个组合中的一个触发了 token 阈值并拒绝后续工具，整组 token 未减少。金额与时间阈值分别用固定价格、固定时钟的单元测试验证。压缩共写入十次摘要，增加了额外调用。流式组都在整轮返回前收到文字增量，提前约 2.9、62.0、3.4 秒，终端将其用于生成进度。

小样本中答题表现较弱。保留预算、压缩和流式独立开启，默认值维持可选。费用显示使用模型的实报用量和配置费率。原始结果、会话与参考清单保存在本地 `evals/results/v02-controls/`。

## 审查回归

手写开发语料检出 21/24 个注入错误，137 条结论中没有命中干净结论。本地 Qwen 在同一批任务上重新生成了 163 条未参与规则调参的结论。离线留出检查检出 29/31 个注入错误，其中引用捏造 14/14、执行声明 6/6、数值 9/11。按注入评分口径，有 9 条发现落在未注入错误的结论上。这个结果衡量对该模型回答风格的泛化。

uv run python evals/review_eval.py
uv run python evals/review_eval.py --heldout ollama:qwen3:4b-instruct
