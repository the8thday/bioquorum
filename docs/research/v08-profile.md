## 已冻结的比较顺序

对照臂为同一留出题的 current。先在 A、B、C 各取第 25 题，依次只改变下表的一项。预算允许时按 26、27、28、21、22、23、24 的顺序继续。29、30 专用于第一天人工对照。不给 worker 评分项。研究、审查、评分的计费口径和 0.8.1 相同。各配置与 current 的完整配对题数、覆盖分子及分母、耗时和费用必须一起报告。少量配对只支持探索性观察。不能由一个开关的独立成绩推算多开关组合成绩，候选组合须另跑确认。

| 配置 | 实际改变或可测条件 |
|---|---|
| coverage | 可声明子问题、绑定实查记录、登记缺口，附范围检查 |
| first_pass | 固定四段收尾，可在检索前留一个澄清问题；另记触发会话数 / 执行会话数 |

| binding_retry | 未解析绑定最多退回一次 |

| project_notes | 开放项目笔记；单轮空白项目没有跨会话笔记可复用 |
| literature | A/C 可委派单独的只读文献检索，白名单只含检索和读摘要 |
| compact | 上下文达到 32 KiB 时允许压缩；无触发要单列 |
| 通用项目 Skill、追问引用、视觉 | 本轮无项目自带 Skill、前一轮引用或随题图片。单轮题不能回答这些机制在适用任务中的收益。已有专项试验见 v05、v07 研究记录 |
| 流式输出、费用显示、计划审批、资源上限 | 交互或资源配置，展示、等待人工和限额的行为有独立测试；本轮统一工况 |

离线列出所有组合用 `uv run --no-sync python evals/run.py --profile ablations --list`。真实运行用 `uv run --no-sync python evals/run.py --profile ablations --max-usd 50 --retry-incomplete`。若保守预留达到上限，余下配对保留未测状态。

启动器升级后，已保存的串行结果照常复用，后续会话默认四路并行。报告耗时增减时应同时列出两臂的并发上限，避免将限流或共享计算资源的等待时间解释为机制开销。
