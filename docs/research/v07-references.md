# 选中数值后的追问对照

在同一份记录中列出两个值相同的结果和各自算法。研究者选中其中一个并问“这个数是怎么算的”。开关关闭时，模型看见两个结果但无法从问题中确定选中哪一个，回答无法判断是合理的。打开时，模型还收到所选值原来那次运行的代码、输入哈希和值声明。比较能否同时指出正确的聚合操作与输入列，另记主动表示无法判断的次数。

题目、标准答案与划分已固定在 `evals/v07_references.py`。开发集 1 题，留出集 2 题，每题分别开关各一次。离线浏览器验收使用按请求内容匹配的 cassette，检验选中的数、代码及其出处。作者在自己的终端使用 OpenAI gpt-6.1-sol 跑完全部六次请求。

| 数据集 | 引用 | 算法与列均正确 | 回答无法判断 | 输入 / 输出 token 合计 | 请求耗时合计 |
|---|---|---:|---:|---:|---:|
| 开发集 | 关 | 0/1 | 1/1 | 70 / 52 | 7.97 秒 |
| 开发集 | 开 | 1/1 | 0/1 | 200 / 13 | 3.18 秒 |
| 留出集 | 关 | 0/2 | 2/2 | 140 / 72 | 25.19 秒 |
| 留出集 | 开 | 2/2 | 0/2 | 411 / 27 | 14.05 秒 |

三次关闭引用时模型均按要求表示无法判断。打开后，两道留出题分别识别了对 read_depth 取最小值和对 weights 求和。每题只跑一对，结果说明这三个同值歧义案例得到消解；耗时和正确率不能外推到其他任务。项目未配置价格，费用未知。

在已导出 OpenAI 密钥的终端运行 `uv run --no-sync python evals/v07_references.py`。共 6 次 worker 请求，无 reviewer 或工具调用。每次请求后写入结果文件 `evals/results/v07/references.json`，保存答案、用量和耗时。未配置价格时费用为空。
