# v0.9 场景 B · 配对供者的 Python 和 R 分析

## 研究问题

用 GSE96583 batch 2 比较同一供者的刺激与对照 CD14+ 单核细胞。Python 沿用 v0.5 的条码匹配、作者标签、过滤阈值和基因预过滤。R 使用 DESeq2，模型为 `~ donor + condition`，对比方向为 stim 对 ctrl。样本单位是供者和条件的组合。两种方法的显著基因数可以不同。

## 已实测的输入与交接

在本机 macOS 沙箱，用实际 Python kernel 和已核对 SHA-256 的三个 GEO 文件计算。两个文库均未观察到线粒体 UMI，因此无法用这批计数评价线粒体比例。分析保留作者标注的 singlet，要求每个细胞至少检出 200 个基因，每名供者在两个条件分别至少有 30 个合格的作者标注 CD14+ 单核细胞。供者对中任一条件的基因计数至少为 10，且至少有 3 对满足，才纳入两种统计方法共同使用的基因集合。

| 交接文件 | 实测结果 | SHA-256 |
|---|---|---|
| paired-counts.csv | 5,140 个基因 × 16 个供者条件样本，非负整数 | `7550acff0644d93db619279db4e72c6aa7a24c079d68a4d2baea87be050090d6` |
| paired-samples.csv | 8 名供者，各有一个对照和一个刺激样本 | `61f31cfe06dfd687805656cea00dfce80aef242304debc453f169a859efd658f` |

本机 R 4.6.0 独立读取了这两份 CSV。实际计数列名与样本表完全同序，每个供者有完整配对，设计矩阵 9 列、秩为 9。Python 阶段的独立研究包重跑报告了输出匹配和环境指纹匹配。

## 真实 DESeq2 结果

项目锁提供 R 4.5.3、IRkernel 1.3.2、DESeq2 1.50.2。macOS 的 seatbelt 和 Linux 的 bubblewrap 各自从相同的原始文件运行了同一个双语言会话流程。两次均得到 8 名配对供者和 16 个样本。共 5,355 个符合条件的 CD14+ 单核细胞，其中对照 2,770 个、刺激 2,585 个。13 个线粒体基因行在两个文库的计数均为零，线粒体比例这一条件无法用于筛除细胞。

按供者和条件加总原始整数 UMI，以供者作为区组，DESeq2 拟合 `~ donor + condition`。刺激相对于对照的比较使用 `alpha = 0.05`。预过滤的 5,140 个基因均有非缺失的调整后 p 值。其中 2,896 个满足 BH 调整后 p 值 ≤ 0.05，1,460 个点估计为正，1,436 个为负。方向按未收缩的 log2 fold change 符号统计。科学结论限定于本批次、此细胞类型和这套预过滤条件。

工作台已实测点击 R 的 2,896 能看到 DESeq2 代码、上游 Python 代码和计数文件哈希，点击 Python 的供者数能看到 GEO 输入。实际输出为示例项目内的 `outputs/v09/deseq2-results.csv`。

## 重跑与独立重复

- macOS 研究包在独立的同平台锁定环境重跑，两个单元的输出及环境指纹均匹配。
- Linux 在启用 bubblewrap 的临时机器生成原始记录。另一只 Linux ARM64 容器独立按锁安装环境，断开网络后执行 `rerun.sh`。容器中没有 BioQuorum，两个单元的输出及环境指纹均匹配。研究包及日志在本地 `evals/results/v09/01M7Z584V49KPW3S3FC6YHGQEK.zip` 和 `evals/results/v09/linux-clean-replay.log`。
- 把 macOS 研究包直接带到 Linux 时，两个交接文件哈希仍然相同，完整精度的 DESeq2 CSV 哈希不同，严格重跑按设计报告差异。按基因键核对，5,140 个基因的顺序相同，2,896 个入选基因完全一致。调整后 p 值的最大绝对差为 4.34 × 10⁻¹¹ 以内，log2 fold change 的最大绝对差为 1.72 × 10⁻⁹ 以内。各平台的完整结果和精度均保留。
- 对“有多少名供者在两种条件下各有一个样本”另作应用内盲重复。原始 R 运行先在新 bubblewrap 内核精确复现。新 OpenAI worker 收到样本表、问题、单位和目标定义，自行编写 R 代码，得到 8 名供者，零容差匹配。此项盲重复仅覆盖供者数。
