# v0.5 文献子任务对照

2026-11-19 在同一台 Mac 上用本地 Ollama 的 `qwen3:4b-instruct` 配对运行。每次用新会话，双方使用同一个模型和同一个合成文献工具。关闭时由主模型直接检索，开启时在同一问题前加 `/literature`，由子任务先检索。工具返回固定的本地记录。评测从回答检查预设答案和实际绑定，从事件检查委派是否完成。用量统计包括子任务调用，耗时包含整个回答回合。

## 最终入口，新留出题

| 指标 | 直接检索 | 显式 `/literature` |
|---|---:|---:|
| 答案含预期内容 | 1/3 | 3/3 |
| 至少一条有效绑定，且全部绑定通过 | 1/3 | 2/3 |
| 子任务返回经核对的摘录 | 0/3 | 3/3 |
| 平均模型 tokens | 1,046 | 1,606 |
| 平均耗时 | 3.41 秒 | 4.42 秒 |

直接检索时，模型两次判断合成档案问题超出范围，未调用可用工具。显式触发时，每题都取得了原文。一题的主回答把引句与 `[@s1]` 分开写，未通过规范的引用绑定。三个问题的答案评分只查预设值，额外的模型陈述仍需单独审查。后来场景 A 验证了真实 Europe PMC 检索和引用回溯。多轮搜索及其它模型上的提升仍待评测。每个项目默认关闭。 [场景 A](v05-scenarios.md)

## 开发探索

早期版本让主模型在直接工具和子任务间自行选择。开发题 1 道，两组均无有效引用。第一批留出题 3 道，两组各有 3 道通过，开启侧未委派。随后试过在开启侧只给主模型委派工具。另一批留出题 3 道，直接检索 1 道通过，开启侧 0 道通过且主模型仍未委派，随后恢复直接检索入口。以上题目各自只用于对应的开发对照；最终显式入口使用另外三道题。

## 复跑

用已经包含 `qwen3:4b-instruct` 的本地 Ollama 模型目录。脚本临时启动本地服务，结束时关闭。逐题答案和指标保存到指定 JSON。

```bash
uv run python evals/v05_literature_eval.py --set explicit \
  --models-dir /path/to/ollama/models --output evals/results/v05/literature-explicit.json
```
