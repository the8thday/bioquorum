# v0.2 绑定失败修复对照

2026-11-19。共 66 个主评测组合，另有 1 次运营复跑。比较 DeepSeek V4 Pro 与 Flash 两个模型，两个模型使用同一 API 服务。前一轮自然答题中没有触发自动退回，这轮从已知有错的标记出发，测触发后能否修好。 [首轮绑定评测](binding-eval.md)

## 方法

- 冻结 3 道开发题、8 道留出题，各含 1 道正确对照。留出题共有 8 条故意置错的目标结论，其中 4 条是不存在的变量名，4 条是原话引错来源。另外保留一条正确的相邻数值结论，用来检查改写是否误伤。
- 每个模型、题目都在三个新会话里独立跑 0、1、2 轮上限，并随题目轮换运行顺序。通过生产 `run_turn` 和正常的工具、事件及退回路径注入同一组固定工具结果和起始回答。前两次响应为脚本回放，台账不计作付费调用。真实调用从第一次反馈开始。数值通过 `FakeKernel` 回放为正常的 `bq.value` 事件，原话通过冻结来源工具返回。不存在真实计算和数据库检索。
- 自动评分要求答复保留目标结论、显示正确值、绑定到正确的命名记录或引用正确来源。自动评分使用固定标签和较保守的字面规则。人工复核逐条检查原答案和引用，接受保留语义的改写。去掉标记、撤回结论、选中同值的错误记录，以及 API 失败都计为未修复。正确对照和正确的相邻结论另外统计。
- 公开价格表的高峰费率乘以已返回用量，作为可比较的费用估算。失败请求没有用量。 [DeepSeek 价格表](https://api-docs.deepseek.com/quick_start/pricing/)

## 结果

分母只含预置错误结论。三档配置都包含正确对照，两模型的 12 个对照组合原样通过，全程无真实调用。

- **一轮反馈有实际修复效果。** 留出集中，V4 Pro 修好了 4/4 条变量绑定和 4/4 条引文绑定。Flash 修好了 3/4 条变量绑定和 4/4 条引文绑定。Flash 在两种启用退回的配置下都撤回了 `heldout-intact-neighbor` 中本来正确的检测数。模型质疑脚本中直接声明的数值是否来自原始数据，说明采用回放数值会影响针对计算场景的外推。
- **第二轮没有实际触发。** 36 个有预置错误且允许退回的组合都触发了一轮反馈。上限为 1 和 2 的独立运行中分数、调用数与费用的变化来自不同的生成轨迹。V4 Pro 的一轮配置中，有一题触发 10 次工具调用后用无工具收尾才答对。一轮反馈可能带来多次模型调用。
- **首次错误保留在主结果里。** V4 Pro 的 `heldout-intact-neighbor` 在上限 2 组调用 Python 回放工具后，DeepSeek 以缺少 `reasoning_content` 拒绝下一次请求。该臂先前已有 1 次完成的付费调用，费用从事件补计。单独复跑时，该题的错误绑定得到修复，相邻的正确绑定也保留，增加 2 次完成的调用。复跑结果与主结果独立保存。
- **人工加回的目标逐项留痕。** 开发集加回 Flash 上限 2 的 `dev-source`。留出集加回 V4 Pro 上限 2 的 `heldout-endpoint`，Flash 上限 1 的 `heldout-complete-pairs`、`heldout-endpoint` 和 `heldout-mixed` 的最终样本数，Flash 上限 2 的 `heldout-control`、`heldout-endpoint`、`heldout-mask` 和 `heldout-mixed` 的主要读出。差异来自等义复述、有效的运行号说明，或同时报告了另一个有据且明确区分的数值。Flash 上限 2 撤回的最终样本数不计为修复。

主评测 60 次完成的模型调用，复跑 2 次。按高峰费率和返回的用量估算，共 **0.05882 美元**。一次失败请求无用量，实际账单未核对。
