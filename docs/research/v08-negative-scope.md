# 否定性陈述的范围检查

覆盖开启时，系统区分一次具体的空查询与推广到整个领域的断言。有效的空返回要能回到当前问题中的查询编号、工具、检索词和实际结果。失败的查询无法证明空结果。工作台单列有关提示；审查时越界断言保持“仅为断言”。

| 材料 | 单位 | 发现越界 / 已知越界 | 误报 / 已知无越界 |
|---|---|---|---|
| 开发用注入案例 ie-025 | 该案例两条陈述 | 1 / 1 | 0 / 1 |
| 冻结规则后另取的模型回答 | 既有 Qwen 记录中的七段原文 | 1 / 1 | 2 / 6 |

七段原文由人工选取，含材料缺失、领域结论和主动提醒读者限制范围的表述。两条误报都是“提供的材料没有给出证据”一类的表达。样本小且经选择，不能据此估计生产环境的召回率。该样本不参与调规则。完整 60 会话基线使用旧默认配置，两项评测的分母不同。排序、完整性和事件来源另有确定性单元测试。[留出原文及标签](../../evals/questions/v08/absence-heldout.yaml)

全部手写案例的确定性检查合计抓到可测类型的 22/25 个注入错误，共 139 条陈述、0 条误报。对既有 24 个模型生成案例复跑原有检查，抓到 29/31 个错误，163 条陈述中误报 9 条。以上两组总体数字均包含其他错误类型。

开发集和既有模型集分别运行：

```sh
uv run --no-sync python evals/review_eval.py
uv run --no-sync python evals/review_eval.py --heldout
```
