## 运行协议

```bash
uv run --no-sync python evals/run.py --profile baseline --split heldout --max-usd 50 --retry-incomplete
```

按题目配对评分。两个角色均用 OpenAI GPT-6.1 Sol。每臂使用独立空白项目、隔离且不能联网的 kernel、相同题面、相同最大探索步数和相同输出上限。minimal 只给 Python 工具和简短提示；current 使用当前默认 Agent 开关和内置工具，A/C 同时提供 v0.5 的六个公开查询工具。A/C 两臂的外部检索能力因此不同，本轮用来测产品配置整体表现。后续通用 Agent 对照须使用相同可用来源。

开发集（`--split development`）默认用 GPT-6.2 Sol 做研究、审查和评分，结果保存在 `evals/results/v08/models/gpt-6.2-sol/development/`。复跑历史开发结果可指定 `--worker openai:gpt-6.1-sol`，审查和评分会使用同一模型。两种模型共用累计预算账本。留出集的基线与配对消融固定用 GPT-6.1 Sol。[GPT-6.2 Sol 模型说明](https://developers.openai.com/api/docs/models/gpt-6.2-sol)

评测启动器默认 `--jobs 4`，按冻结队列分派至多四个独立会话，每个会话依次执行研究、审查和评分。各自的项目、kernel 和用量记录独立，同一批次共用原累计预算账本；预算临时被在途请求占用时，等其结算后再尝试预留。需要复测串行耗时可用 `--jobs 1`。新写入的结果用 `campaign_jobs` 记录启动时的并发上限，字段缺失的旧记录均为串行。累计会话耗时会计入重叠时段，与终端命令的实际历时分开解读。

计分单位是题目预先定义的证据类别。评分模型在回答结束后读取评分标准、回答、取回的来源和成功运行记录，逐项返回能支撑得分的回答原句；程序逐字验证，未达到标准记零。该分数属于模型初评。科学评分权归作者。按所有评分项合计计算覆盖率，分母不按调用次数改变。另报各可信度等级结论数和有据占比（有据及以上的条数除以抽取的全部结论）。失败、解析失败、审查中断和没有可评结论保留记录，全组不完整时不发布完整覆盖率。工时为逐题实耗时间之和。费用为按记录用量和标准输入输出价估算的金额，实际账单可能受缓存影响。

评测共用本地预算账本。初次运行按完整模型窗口预留；续跑改用官方免费输入 token 计数端点，按相同输入、工具定义和最大输出计算每次生成调用的保守预留。有完整用量后释放多余部分。初次运行的未知用量预留继续保留。断网或用量未知时保留预留，余额不足会提前停止。并发和进程重启共用同一份记录。研究、审查和评分都经过这一入口。请保留 `evals/results/v08/spending.sqlite`。计数与生成分开计费的规则见 [OpenAI 计数说明](https://help.openai.com/en/articles/4936856-understanding-and-counting-tokens)。价格、上下文和长输入规则见 [OpenAI 模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。
