# BioQuorum 产品定义

> 状态：**v0.4（2026-11-17）**，与 [DESIGN.md](DESIGN.md)、[ARCHITECTURE.md](ARCHITECTURE.md) v0.4 和 [ROADMAP.md](../ROADMAP.md) 同步。v0.4 的改动：定位改为"研究记录"；支柱 2 改写为证据绑定加可信度阶梯（ADR-014、015）；Web 工作台提前（ADR-016）；发布标准改为以 60 秒演示为准。旧版存档于 archive/。
> 本文描述的是目标产品。已经实现了什么，以 README 和 CHANGELOG 为准。
> 名称 **BioQuorum** 已确认。PyPI 和 GitHub 上暂无同名项目，商标还没有查。
> 寓意：生物学里的 *quorum sensing*（群体感应），加上"独立重复得到一致的结果（quorum）才算可信"。

## 1. 一句话定位

**面向生物医药研究的开源科研 agent。它交出来的不是一段回答，而是一份研究记录：每个数字连着算出它的代码，每条引用连着原文里的那句话，每个结论标着它被验证到了哪一步。不绑定模型，运行在你自己的机器上。**

English: *The open research agent for biomedicine that shows its work — every number traces to the code that computed it, every citation to the sentence that supports it. Any model, on your own machine.*

## 2. 为什么需要它

| 现状 | 问题 |
|---|---|
| Claude Science 等商业工作台 | 只能用一家的模型；数据要发给厂商；自己检查自己（Reviewer 和主 agent 用同一个模型） |
| 现有开源替代（三个 openscience 项目） | 通用功能已到 70 到 80 分，也有 reviewer 或验证证据、也有导出包。但审查仍是同模型自审且不重跑，导出包不能脱离应用重跑，私有化合规没有做 |
| 科研人员的真实顾虑 | "AI 给的结论能不能信？""半年后还能重跑出来吗？""公司数据能不能用？" |

BioQuorum 就是要回答这三个问题。三个问题背后是同一件事：**核对一条 AI 结论的成本太高**。我们把它降到点一下鼠标（见 [DESIGN.md](DESIGN.md)）。

## 3. 目标用户

| 角色 | 需求 | 版本优先级 |
|---|---|---|
| **计算生物学家 / 生信分析师**（主要用户） | 加速组学分析、查数据库、出图，同时代码和过程可追溯 | v0.1 起（CLI；会用 Claude Code 的用户可直接通过 MCP 使用） |
| **湿实验科学家 / 药物化学家**（扩展用户） | 不写代码，问靶点、文献、化合物问题，要带引用的可靠回答 | v0.3 起（Web 工作台，ADR-016） |
| **研究平台 / IT 负责人**（部署者） | 能自托管、自己控制模型和成本、有审计、数据不外泄 | v0.6 起 |

## 4. 三个北极星场景

所有功能都围绕这三个场景设计。它们也是 demo、示例项目和评测集的来源。

**A. 靶点评估档案（Target Dossier）**
> "评估一下 GENE_X 作为 IBD 靶点的潜力。"

依次收集：遗传学证据（Open Targets、GWAS Catalog、gnomAD）、表达谱（GTEx、HPA）、可成药性（ChEMBL、PDB/AlphaFold）、文献、竞争格局（ClinicalTrials.gov）。最后生成一份带引用的报告，每条结论都经过交叉审查。

**B. 组学数据分析（Omics Analysis）**
> "用 GSE_xxxxx 做单细胞 QC、聚类和差异表达，出发表级的图。"

整个过程在常驻 kernel 里执行。每张图都能追溯到生成它的代码、环境和输入数据，并且可以导出成别人能重跑的研究包。

**C. 证据综述（Evidence Review）**
> "化合物 Y 在 Z 疾病里有哪些机制证据？"

检索文献，整理成证据表。每条引用都核实过（DOI 能解析，内容确实支持结论），矛盾的证据会单独标出来。

## 5. 五大支柱

### 支柱 1 · 模型中立（Model-neutral）
- 支持 Anthropic、OpenAI、Google、DeepSeek、Qwen，以及任何 OpenAI 兼容接口（vLLM、Ollama、LM Studio、OpenRouter、LiteLLM Proxy）
- **按角色配置模型**：planner（规划）、worker（执行）、reviewer（审查）、summarizer（压缩上下文），各用各的模型
- 每次调用的 token 和费用都可见，可以设置项目预算
- 失败时自动回退到备用模型

### 支柱 2 · 有据可查，逐级验证（Grounded and verified）
这是**核心差异化**，名字里的 Quorum 指的是最高一级：独立重复。
- **证据绑定**（ADR-014）：报告里的数字是从 run 的输出里取出来填进去的，不是模型打出来的字；每条引用带一句原话，能在检索到的来源里逐字找到。点数字看代码、输出和输入数据；点引用看原文。模型凭记忆写的内容不拦截，但明确显示为"仅为断言"
- **可信度阶梯**（ADR-015）：`仅为断言` → `有据` → `已审查` → `已复现` → `已独立重复`，出问题则为 `有争议`。每一级靠机制得到，不靠模型的口气；不适用的级别显示"不适用"
- **审查**：四个不花模型调用的确定性检查，加 reviewer 模型的判断类检查（这句原话是否支持这条结论、统计方法是否得当）。Reviewer 按审查评测成绩选择（ADR-013）；对照实验没有发现同模型自审的盲区，所以不宣传"跨家族更准"
- **复现**：在全新的 kernel 里重新执行同一份代码，对比结果
- **独立重复**：另一个 agent 只拿到问题、数据和要计算的量的定义，不知道原来的答案，自己重做一遍。一致则升级；不一致就把两边的方法和数值并排给人看

### 支柱 3 · 默认可复现（Reproducible by default）
- 每个产物都有版本，并记录代码、环境锁文件、输入数据的 hash、生成它的对话片段
- 一键重跑任意版本
- **研究包（Research Bundle）是开放格式**，有公开规范（`bundle-spec/`）：不装 BioQuorum、只装 pixi 就能用 `rerun.sh` 重跑，并按 `run_key` 自动比对结果；可以附在论文后面，也可以交给审稿人。manifest 从 v0.1 起就记录，导出功能晚做但数据不缺
- 自动生成 Methods 段落草稿

### 支柱 4 · 私有优先（Private by design）
- 在本地或自己的服务器上运行，**默认零遥测**
- 模型生成的代码在隔离的 kernel 里运行，默认不能联网；联网只能经过有权限、有审计的工具（ADR-017）
- **项目数据分级**：`public` / `internal` / `confidential`
  - 模型路由强制遵守分级规则，例如 confidential 项目只能用本地模型或白名单里的模型
- 审计日志：每次模型调用（发给了谁、什么分级、多少 token）、每次对外网络访问，都有记录
- 密钥存放在系统钥匙串里，不会出现在模型上下文中

### 支柱 5 · 生物医药深度（Biomedical depth）
- 精选的数据库连接器：质量第一，每个都有测试，并标注数据许可（学术/商用）
- 精选的 Skills 包：组学、靶点、化学信息学、结构生物学
- 专业的查看器：分子（2D/3D）、蛋白结构、基因组轨道、大表格
- 兼容生态：可以导入 Agent Skills（SKILL.md）和任意 MCP 服务器

## 6. 竞品对比

| | Claude Science | openscience 系（3 个开源项目） | **BioQuorum** |
|---|---|---|---|
| 模型 | 只有 Claude | 多模型 | 多模型 + 按角色分配 + 按策略路由 |
| 审查 | 同一个模型自审，不重跑 | 同模型 review pass（synthetic-sciences）、验证证据（aipoch），都不重跑 | **写出时绑定证据 + 结论级确定性检查 + 可重跑 + 独立重复** |
| 复现 | 只能在应用内使用 | `.science` 包（aipoch，可在应用内重放） | **开放规范 + 脱离应用的 `rerun.sh` + 自动比对** |
| 私有化 | 数据发给 Anthropic | 本地运行，部分项目默认上传 trace | 零遥测 + 数据分级路由 + 审计 |
| 领域 | 生物为主，覆盖面广 | 通用科研 | 聚焦生物医药 / 药物研发 |

## 7. 不做什么（v1.0 之前）

- 不做通用编程 agent（那是 opencode / Claude Code 的事）
- 不做湿实验自动化或机器人控制
- 不做临床诊断或决策支持
- 不做多租户 SaaS 托管服务
- 不训练自己的模型
- 不做 HPC 和云算力调度（v1.0 之后再做）

## 8. 产品形态

| 形态 | 说明 | 版本 |
|---|---|---|
| CLI | `bq run`、`bq review`，后续 `bq rerun`、`bq export`，可以写进脚本 | v0.1 |
| **MCP Server 模式** | 把科学层（kernel、溯源、连接器、审查）暴露给 Claude Code、opencode、Cursor 等工具使用 | v0.1 |
| Web 工作台 | 启动本地服务，自动打开浏览器；以研究记录为中心 | v0.3 |
| `uvx bioquorum` / `pip install bioquorum` | 一条命令安装，不需要 Node | v0.3 |
| Docker 镜像 | 部署到团队服务器 | v0.6 |
| Python SDK | 在代码里调用 | v0.6+ |
| 桌面应用（Tauri） | 一键安装 | v1.0 之后 |

## 9. 信息架构

```
Workspace（一次安装 / 一台服务器）
└── Project（项目：数据目录、数据分级、模型策略、Python 环境）
    ├── Sessions（会话：对话、计划、运行记录，可以分叉）
    ├── Artifacts（产物：图、表、报告、数据，带版本和验证状态）
    └── Bundles（导出的研究包）
Library（库）：Skills · Connectors · Specialists（自定义 agent）
Settings（设置）：Models & Roles · Policies · Credentials · Audit Log
```

界面布局（v0.3 起，ADR-016）：中心是研究记录，对话是方向盘。
```
┌────────────┬───────────────────────────────────┬──────────────────────┐
│ 项目/会话   │ 研究记录                            │ 证据抽屉（点开才出现） │
│            │ · 问题与计划（待批准 / 进行中）       │ · 数字 → 代码、输出、  │
│            │ · 发现：每条结论带状态标记            │   图、输入数据 hash   │
│            │   ● 有据  ● 已审查  ● 已复现          │ · 引用 → 原文，       │
│            │   ● 已独立重复  ○ 仅为断言  ▲ 有争议  │   原话高亮           │
│            │ · 图和表                            │ · 审查发现、重跑和     │
│            ├───────────────────────────────────┤   独立重复的对比      │
│            │ 活动流：agent 正在做什么；权限卡片     │                      │
│            │ [输入框：提问、打断、改方向]          │                      │
└────────────┴───────────────────────────────────┴──────────────────────┘
```
布局是第一版的出发点，做出来后由作者按 DESIGN.md 第 4 节的演示走一遍再定。

## 10. 发布标准

发布分两步。

**可安装（v0.3，不做宣传）**：
- [ ] `uvx bioquorum` 一条命令装好并打开工作台，5 分钟内跑通示例
- [ ] 不碰命令行完成场景 C
- [ ] `SECURITY.md`（如实写出隔离的边界）、`CONTRIBUTING.md`、`THIRD_PARTY.md`、Apache-2.0 LICENSE
- [ ] CI：测试、lint、类型检查、import-linter 全部通过

**正式发布（v0.4）**，以 [DESIGN.md](DESIGN.md) 第 4 节的 60 秒演示为准，演示里的七步都要是真的：
- [ ] 演示录屏放在 README 首屏；三个北极星场景各有一个示例项目
- [ ] 至少 3 家模型（含 1 个开源模型）实测，公布评测报告：harness 提升（同一模型裸跑对比带 harness）、绑定遵从率、编造内容检出率、独立重复的假不一致率；看过的和没看过的数据分开写，确定性检查与模型检查分开写
- [ ] 导出的研究包在干净机器上用 `rerun.sh` 重跑成功
- [ ] 文档站：快速开始、概念、配置模型、作为 MCP Server 使用、写 Skill / Connector
- [ ] 发布流程自动化

## 11. 成功指标

- **核对成本**（首要指标）：读者核实一条结论需要的操作数和时间；报告里有据的数字和引用所占比例
- **质量**：自建评测集（3 个场景 × 约 30 题）分数；harness 提升（ADR-018）；Reviewer 对人工注入错误的召回率和误报率，确定性检查与模型检查分开统计；判断类检查上跨家族 reviewer 相对同家族的增量（ADR-013）
- **复现**：导出的研究包在干净机器上重跑成功的比例
- **采用**：GitHub star、PyPI 下载量、外部贡献的 Connector / Skill 数量
