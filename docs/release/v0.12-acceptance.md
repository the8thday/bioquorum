## 一万条事件的实测

使用相同解释器、同一数据库与本地 Chrome。固定会话含 100 轮，混合问题、计划进度、工具失败、回答及完成事件。每项三次取中位数，浏览器连续加载三次，首次加载也计入。结果反映本机这个合成会话；真实研究会话里大量图片或大段工具正文可能产生不同耗时。

| 耗时 | v0.11 | v0.12 |
|---|---:|---:|
| Chrome 打开至最后一张可见答案卡出现 | 1327.75 ms | 203.98 ms |
| 从底部滚到顶部，等两帧确认位置 | 25.9 ms | 33.2 ms |
| SSE 从序号 9899 续传至 9999 | 96.3 ms | 4.0 ms |
| 服务端构建完整会话快照 | 858.67 ms | 158.30 ms |
| 按游标读 50 条审计事件 | 59.78 ms | 0.74 ms |
| 完整重建投影 | 305.12 ms | 269.96 ms |

工作台首屏限制渲染轮数，服务端在顺序读记录时增量构建各答案的证据。审计分页按序号和事件类型查询；SSE 每次取一批，投影重建只反序列化有处理器的事件。滚动指标包括浏览器调度，本次测量比基线慢 7.3 ms。[数据生成与服务端计时](../../evals/v12_long_session.py) · [浏览器计时与分页检查](../../tests/e2e/long_session.cjs)
