# v0.6 私有部署开发验收

Linux 一列是 2026-11-20 在 Ubuntu 24.04 服务器上的结果（bubblewrap 可用，Docker 29.1，
网络把公开域名解析到公开地址）。

| 项目 | macOS 本机结果 | Linux 服务器结果 | 待核对范围 |
|---|---|---|---|
| 分级与工作台审计 | 浏览器回归通过。会话范围、分页和原始参数排除已测试。 | 未重复（与平台无关）。 | 作者界面验收。 |
| 内核隔离 | 真实 confidential Jupyter 会话通过私有 IPC。项目外文件、会话状态、配置写入与 IP 联网被拒绝，项目输出可写。 | confidential 和 public 项目都在 `bwrap` 中运行，隔离模式记入 `run_started`。`integration` 测试 18 个通过，另 3 个只在 macOS 上运行。 | 其它 macOS 版本。 |
| 离线 stdio MCP | 本机启动真实 SDK stdio 服务，正常工具调用，项目文件读取被拒绝。 | 通过。隔离的 MCP 服务读不到项目文件、仓库源码和 `~/.ssh`，连不上本机回环、外网和 DNS，宿主机的环境变量不会传进去，只能写自己的临时目录。已固定为 `tests/integration/test_linux_mcp_isolation.py`。 | — |
| HTTPS 出站代理 | 允许路径的本地隧道、拒绝域名与拒绝非公开地址通过。Mac 和本机 Linux VM 把外部域名解析到非公开地址，实际往返未测。 | 通过。`eutils.ncbi.nlm.nih.gov` 解析到公开地址，经代理返回 200。在配置了 `[security] outbound_proxy` 的项目里，`download_file` 实际下载成功，sha256 记入事件。白名单外的域名、直接写 IP 和明文 HTTP 都被拒绝。 | — |
| 开发分发包 | 已从源码离线生成 `0.6.0.dev0` wheel 和 sdist，并逐成员检查。 | 在 Linux 上离线重建，`scripts/check_distributions.py` 通过。 | 正式发布由作者决定。 |
| Docker | 本机没有基础镜像。 | 镜像构建成功。CLI 以 UID 10001 运行，`project init`、`project show`、`sessions`、`tools`、`models` 正常。默认容器策略下，容器里的 bubblewrap 无法创建用户命名空间：confidential 项目明确拒绝启动 kernel，public 项目以 `isolation = none` 运行并记录。放宽 seccomp 和 AppArmor 后仍不可用，因为宿主机设置了 `kernel.apparmor_restrict_unprivileged_userns = 1`。 | 敏感数据请直接在宿主机安装运行，不要用容器。是否放宽宿主机的用户命名空间限制，由部署方决定。 |
| 服务器和本机模型 | 已记录 SSH loopback 访问、模型端点、离线 MCP 和 HTTPS 出站配置。 | 远程模型（OpenAI Responses、DeepSeek）在服务器上实测可用。没有安装 Ollama，本机模型路径没测。 | 本机模型端点的端到端演练。 |
